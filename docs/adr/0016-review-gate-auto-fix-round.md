# ADR-0016: 리뷰 게이트에 자동 수정 라운드를 추가한다

- 상태: 승인됨
- 날짜: 2026-08-10
- 관계: [ADR-0013](0013-issue-triggered-agent-harness.md)의 "조건부 승인" 결정을 대체(superseded)한다. ADR-0013의 다른 결정(러너 환경, 인증 방식, 이슈 트리거 흐름)은 유효하다. [ADR-0005](0005-local-agent-orchestration.md)의 "자동 머지 금지" 원칙은 유지한다. GitHub 이슈 #292, `docs/specs/025-review-gate-auto-fix/spec.md`·`plan.md`를 구체화한다.

## 맥락

ADR-0013은 `implement-and-open-pr` job이 PR을 연 뒤 자체 리뷰를 한 번 돌리고, 차단(blocking) 0건·권장(recommended) 0건일 때만 조건부 승인하도록 정했다. 그러나 차단 사항이 하나라도 나오면 그 자리에서 멈춘다 — 같은 job 안에서 고칠 방법이 없어, 사람이 브랜치에 직접 커밋을 추가해야만 다시 진행된다(GitHub 이슈 #292). 자동화 흐름 중간에 사람 개입이 강제되는 지점이 남는다.

동시에 "리뷰 결과를 PR에 게시" 스텝에 확인된 버그가 있다. `structured_output`이 빈 문자열일 때 `env`에서 `fromJSON('')`을 즉시 평가해 `if:` 가드와 무관하게 스텝이 failure로 죽는다(2026-08-09 실행 https://github.com/finplay-team/finplay/actions/runs/31333724172/job/93295980910 에서 실측). 자동 수정 라운드를 추가하면 같은 종류의 "리뷰 결과 게시" 스텝을 하나 더 만들게 되므로, 이 버그를 안은 채 복제하지 않아야 한다.

## 결정

- `implement-and-open-pr` job에 자동 수정 라운드를 정확히 1회 추가한다. 라운드 1(자체 리뷰)의 `blocking_count > 0`일 때만 실행된다.
  - 자동 수정 대상은 차단 사항뿐이다. 권장 사항은 고치지 않는다 — 권장까지 포함하면 리뷰어가 만들어내는 지적만큼 PR 스코프가 원래 이슈를 넘어설 수 있다(이슈 #292 propose-directions 코멘트의 공통 권고).
  - 순서: 수정 커밋 푸시 → 러너가 직접 `./gradlew build` 재실행(에이전트의 "빌드 통과했다"는 자기 보고를 검증 근거로 쓰지 않는 기존 원칙 유지) → 자동 수정과 별도의 claude-code-action 호출로 독립 재리뷰 → 재리뷰 결과를 "자동 수정 1회차" 헤더와 종료 사유(차단 해소 / 라운드 소진 / 빌드 실패) 중 하나를 붙여 PR에 게시.
  - 재리뷰를 수행하는 호출은 자동 수정을 수행한 호출과 별도의 claude-code-action 호출이다 — 자기가 고친 것을 자기가 통과시키지 않는다.
- **승인 판정 대상이 바뀐다.** ADR-0013은 라운드 1 리뷰 결과만으로 승인 여부를 판정했다. 이 ADR은 최종 판정 병합 스텝을 두어, 자동 수정 라운드가 실행됐으면 그 재리뷰 결과를, 실행되지 않았으면(라운드 1이 이미 차단 0건이었거나 자동 수정 전제 조건 미충족) 라운드 1 결과를 최종값으로 쓴다. **승인 기준 자체(차단 0건·권장 0건)는 ADR-0013 그대로 유지한다** — 바뀌는 것은 그 기준을 어느 라운드의 결과에 적용하느냐뿐이다.
- 재시도는 최대 1회로 고정한다. GitHub Actions의 step은 반복문을 지원하지 않으므로, 라운드 수는 YAML에 고정 스텝으로 언롤해 구조적으로 상한을 건다(런타임 카운터에 의존하지 않는다). 자동 수정 라운드가 끝난 뒤에도 차단이 남아 있으면 더 이상 자동 재시도하지 않고 사람에게 넘긴다.
- `implement-and-open-pr` job에 `timeout-minutes: 60`을 명시한다 — 기존 흐름(구현 + 빌드 + 리뷰)에 자동 수정 라운드(수정 + 빌드 + 재리뷰) 추가분을 더한 보수적 추정이며, GitHub 기본값(360분)에 암묵적으로 의존하던 상태를 없앤다.
- "리뷰 결과를 PR에 게시" 계열 스텝(라운드 1·자동 수정 라운드 공통)은 `env`에 `fromJSON(...)` 평가 결과가 아니라 raw `structured_output` 문자열만 넘기고, `run:` 스크립트 안에서 빈 값을 먼저 체크한 뒤 `jq -r`로 파싱한다. `structured_output`이 빈 문자열이어도 스텝 자체는 실패하지 않는다.

## 범위 밖

- 재시도 2라운드 이상, 또는 라운드 수를 설정 가능하게 만드는 것.
- 권장(recommended) 사항까지 자동 수정 대상에 포함하는 것.
- 워크플로우 재귀 호출 또는 에이전트 내부 자율 반복(이슈 #292 propose-directions의 2·3안) — 채택안은 같은 job 안에서 step을 언롤하는 1안이다.
- PR 댓글로 재수정을 트리거하는 것(verify-actor의 PR 댓글 제외 조건 변경).
- 사람의 최종 승인·머지 자동화 — ADR-0005·ADR-0013의 "자동 머지 금지" 원칙을 그대로 따른다.
- 하네스 도입 전/후 비교를 위한 지표 수집 스크립트 — `docs/harness-roadmap.md`의 별도 미착수 항목이며 이 ADR의 범위가 아니다.

## 결과

- 차단 사항이 있는 self-review에서도 사람이 개입하지 않고 같은 job 안에서 한 차례 자동으로 고치고 재검증하는 경로가 생긴다. 자동 수정 라운드 소진 후에도 차단이 남으면 기존과 동일하게 사람이 직접 리뷰·승인한다(ADR-0013 승인 기준 유지).
- claude-code-action 호출 수가 라운드당 최대 2건(자동 수정 1건 + 재리뷰 1건) 늘고, 빌드가 최대 1회 더 실행된다 — `CLAUDE_CODE_OAUTH_TOKEN` 소유자의 개인 사용량 한도 소모가 늘어난다(ADR-0013이 이미 안고 있는 한계와 같은 종류).
- "리뷰 결과를 PR에 게시" 스텝의 파싱 방식이 라운드 1과 자동 수정 라운드 양쪽에서 통일되어, 향후 라운드를 늘리더라도 같은 버그를 복제할 위험이 줄어든다.
