# ADR-0013: 이슈 트리거 GitHub Actions 에이전트 하네스를 도입한다

- 상태: 승인됨
- 날짜: 2026-08-05
- 관계: `docs/harness-roadmap.md`의 "이슈 트리거 CI 하네스"를 구체화한다. [ADR-0005](0005-local-agent-orchestration.md)의 "자동 머지 금지" 원칙은 유지한다. PR 승인 자동화는 이 ADR에서 새로 허용하며, 이 점에서 ADR-0007이 참조했던 "자동 승인 금지" 관행과 갈라진다(아래 "결정" 참조). 폐기된 [ADR-0007](0007-codex-ci-review.md)의 Codex CI 자동 리뷰는 재도입하지 않는다. [ADR-0009](0009-codex-local-orchestration.md)가 범위 밖으로 남겨둔 "GitHub Actions에서 실행되는 무인 에이전트"가 이 ADR의 대상이다.

## 맥락

현재(ADR-0005·0008·0009·0010)는 사람이 로컬 Claude Code 또는 Codex 세션에서 `/feature`, `/review-pr`을 직접 실행하는 반자동 체제다. 튜터 피드백(2026-07-23)은 다음 단계로 GitHub Actions 러너에서 에이전트가 이슈를 트리거로 깨어나 동작하는 완전 자동 흐름을 요구했다.

가장 먼저 막히는 지점은 인증이다. 러너 안에서 도는 에이전트는 로컬에 로그인된 어떤 세션과도 무관하므로, Anthropic API를 호출할 별도 크리덴셜이 있어야 한다. 두 방식을 검토했다.

| 방식 | 장점 | 단점 |
|---|---|---|
| `ANTHROPIC_API_KEY` (팀 공용) | 사용량 한도가 구독과 독립적 | 실행마다 API 토큰 비용 발생 — ADR-0005가 애초에 이 비용 때문에 로컬 오케스트레이션을 택했음 |
| `CLAUDE_CODE_OAUTH_TOKEN` (개인 Pro/Max 구독, `claude setup-token`) | 추가 결제 없음 | 토큰 소유자 개인 사용량 한도를 팀 실행이 함께 소모 |

팀장이 Max 구독을 사용 중이므로 팀은 후자를 택했다.

## 결정

- 이슈에 `agent` 라벨이 붙으면 러너에서 에이전트가 실행되어 **코드는 건드리지 않고** 이슈 내용 기반 수정/개발 방향 2~3안을 이슈 코멘트로 제시한다.
- 사람이 코멘트로 방향을 선택하면(예: `@claude 2안으로 구현해줘`) 그 멘션이 트리거가 되어 러너가 재실행되고, 브랜치 생성 → 선택된 방향으로 구현 → 커밋 → PR 오픈(본문에 `Closes #이슈번호`)까지 수행한다.
- 두 트리거는 `.github/workflows/agent.yml` 하나에 정의한다.
- 인증은 `CLAUDE_CODE_OAUTH_TOKEN`을 리포지토리 시크릿으로 사용한다.
  - 토큰은 **팀장이 본인 계정에서 `claude setup-token`으로 직접 발급하고 직접 GitHub Secret에 등록**한다 — 크리덴셜이 다른 채널(메시지 등)을 거치지 않도록 발급자 본인이 등록까지 수행한다.
  - 팀 실행량이 늘어 팀장 개인 사용량 한도가 병목이 되면, 이 결정을 재검토하고 `ANTHROPIC_API_KEY` 방식으로 전환하는 후속 ADR을 쓴다.
- 러너 환경은 `ubuntu-latest`를 쓴다 — Docker가 기본 제공되어 Testcontainers 기반 빌드(`./gradlew build`)가 가능하다.
- **승인은 조건부 자동, 머지는 항상 사람이 한다.** PR을 연 직후 같은 워크플로우 안에서 `.claude/agents/reviewer.md`의 리뷰 모드 기준으로 자체 리뷰를 한 번 더 돌리고, 그 결과가 **차단 0건 · 권장 0건**일 때만 승인(approve)한다. 차단·권장이 하나라도 있으면 리뷰 코멘트만 남기고 승인하지 않는다 — 그 경우엔 팀원이 직접 리뷰·승인해야 한다.
  - 이 자체 리뷰는 이 워크플로우가 스스로 연 PR에만 적용된다. 사람이 올린 PR이나 다른 경로로 만들어진 PR까지 자동 리뷰하는 것이 아니다 — 그건 ADR-0007이 "3중 리뷰 부담"으로 철회한 것과 같은 범위이며, 이 ADR은 그 범위를 재도입하지 않는다.
  - 승인 없이 무조건 승인하는 것과 다르다: 사람이 approve 배지를 보고 실제 리뷰를 생략하는 위험을 줄이기 위해, "이미 리뷰 기준을 통과했다"는 근거가 있을 때만 승인이 붙는다.
  - `gh pr review --approve`는 리포지토리의 "Allow GitHub Actions to create and approve pull requests" 설정이 켜져 있어야 동작한다 (현재 꺼져 있음 — 이 스텝을 쓰려면 켜야 한다).
  - 머지 버튼은 승인 여부와 무관하게 항상 사람이 누른다 (ADR-0005의 "자동 머지 금지" 원칙 유지).
- 이슈 등록 → PR 오픈, 이슈 등록 → 머지 두 시점의 소요 시간을 지표로 기록해 하네스 도입 전/후를 비교한다 (`docs/harness-roadmap.md` "지표" 절 기준). 수집 자동화 스크립트는 이 ADR 범위 밖이며 필요 시 별도로 추가한다.

## 범위 밖

- Codex API 기반 PR 자동 리뷰 재도입 (ADR-0007 폐기 유지).
- 자동 배포·자동 머지.
- 지표 수집 스크립트의 주기 실행(cron) 자동화.
- `ANTHROPIC_API_KEY` 방식으로의 전환 — 팀장 개인 사용량이 병목이 되는 시점에 별도 ADR로 판단한다.

## 결과

- 이슈 등록만으로 방향 제시까지는 사람 개입 없이 진행되고, 자체 리뷰에서 차단·권장이 없는 PR은 승인까지 자동으로 채워진다. 사람은 "방향 선택"과 "머지 실행"(그리고 차단·권장이 있는 PR의 리뷰·승인)에만 개입한다.
- 팀장 개인 Max 구독의 사용량 한도를 이슈 트리거 실행이 함께 소모한다 — 사용량 지표를 주기적으로 확인해야 한다.
- CI 하네스 도입 전/후 비교를 위한 베이스라인 수집(`docs/harness-roadmap.md`)이 이 시점부터 시작된다.
