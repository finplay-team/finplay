# FinPlay 제품 요구사항 문서 (PRD)

## 1. 제품 개요

FinPlay는 코인과 주식을 가상 자산으로 매매해보는 교육형 모의투자 플랫폼이다. 실제 돈을 넣기 전에 매매 흐름을 경험하고, 매매 결과를 기록·복기하며, 다른 사용자와 성과를 비교하고 경험을 나눌 수 있다.

**중심이 되는 시장은 코인이다.** 빗썸의 실제 실시간 시세를 그대로 따라가기 때문에 24시간 거래할 수 있고, 지정가 주문과 시세 도달 시 자동 청산 같은 실시간 시장 특유의 기능을 코인에만 제공한다.

주식은 실시간이 아니라 실제 있었던 과거 거래일의 데이터를 모든 사용자에게 같은 순서로 재생하는 방식으로 보완적으로 제공한다. 일단 지나간 가격은 모두에게 똑같이 확정된 사실이라는 점은 두 시장에 공통이라, 다음과 같은 것들이 가능하다.

- **"다른 시점에 팔았다면 어땠을까"** — 이미 지나간 가격 흐름이 정해져 있으므로, 실제 매도 시점이 아닌 다른 시점에 팔았다면 수익률이 어땠을지 계산해서 보여줄 수 있다.
- **같은 상황을 겪은 다른 사람과의 비교** — 같은 가격 변동 구간을 겪은 다른 회원들이 실제로 어떻게 행동했는지 집단 통계로 보여줄 수 있다. 코인은 실제 발생한 변동 구간을 단위로, 주식은 모두가 같은 재생 세션을 보므로 그 세션 단위로 비교한다.

## 2. 대상 사용자

- **투자 입문자** — 실제 자금을 투입하기 전에 코인·주식 매매가 어떻게 이루어지는지 위험 없이 경험해보고 싶은 사람.
- **매매를 기록하고 복기하려는 사람** — 자신의 매수·매도 판단을 글로 남기고, 나중에 그 판단이 어땠는지 데이터로 돌아보고 싶은 사람.
- **서비스 운영자** — 회원가입부터 매매·기록·커뮤니티까지 전체 흐름이 정상적으로 동작하는지 확인해야 하는 사람.

## 3. 서비스 흐름

1. 이메일 또는 카카오·네이버 계정으로 가입한다. 가입과 동시에 코인 계좌와 주식 계좌가 각각 1개씩, 각 1,000만원의 가상 현금과 함께 만들어진다.
2. (선택) 투자 실습 튜토리얼로 매수·관찰·매도·복기의 한 사이클을 안내받으며 연습한다.
3. 코인은 시장가·지정가로, 주식은 시장가로 매매한다.
4. 보유자산·거래내역·주문목록에서 결과를 확인한다.
5. 매수·매도 각각에 투자일기를 남긴다.
6. 가격이 크게 움직인 구간에서는 AI가 뉴스를 근거로 작성한 변동 원인 서술과, 매도 직후에는 "다른 시점에 팔았다면"·"다른 회원들은 어떻게 했는지"를 확인한다.
7. 랭킹에서 다른 회원과 실현손익을 비교한다.
8. 커뮤니티에 매매 경험이나 종목 의견을 글로 남기고, 실제 매도 체결 결과를 카드로 공유한다.

### 코인과 주식의 차이

| | 코인 | 주식 |
|---|---|---|
| 시세 원천 | 빗썸의 실시간 시세를 그대로 사용 | 실제 있었던 과거 거래일 데이터를 매일 재생 |
| 거래 가능 시간 | 24시간 | 평일 09:00~15:30 (KST) |
| 주문 유형 | 시장가 + 지정가 | 시장가만 |
| 시세 도달 시 자동 청산 | 지원 | 미지원 |
| 차트에 진행 중인 분봉 표시 | 포함 | 미포함(마감된 분봉만) |
| 시세 수신 방식 | 서버가 웹소켓으로 빗썸 체결 틱을 상시 수신해 최신가·진행 중 1분봉을 Redis에 갱신 | 서버가 정해진 시각에 분봉을 재생 |
| 화면 갱신 방식 | 폴링 — 코인 전용 실시간 스트림은 없음 | SSE 구독 |

## 4. 기능 요구사항

### 4.1 회원과 인증

**이메일 회원가입**
이메일, 중복되지 않는 닉네임, 8자 이상 비밀번호, 약관 동의로 가입한다. 가입 전에 이메일 인증을 먼저 통과해야 한다. 비밀번호는 단방향 해시로 저장한다. 가입과 동시에 코인·주식 계좌가 각각 1개씩 생성된다.

**이메일 인증**
6자리 숫자 인증번호를 보내며 **5분간 유효**하고 **5회까지 시도**할 수 있다. 초과하면 그 번호는 즉시 무효화된다. 재발송은 **60초 간격**으로만 가능하고, 같은 이메일로 **1시간에 5회, 하루 10회**까지만 보낼 수 있다. 재발송하면 이전 번호는 곧바로 무효화되어 항상 유효한 번호는 최대 1개다. 인증에 성공하면 **30분간 유효한 1회용 가입 토큰**이 발급되고, 이 토큰으로만 실제 가입이 진행된다.

**로그인**
이메일·비밀번호 또는 카카오·네이버 계정으로 로그인한다. 로그인은 인증 토큰만 발급하며 계좌나 잔액을 새로 만들거나 초기화하지 않는다. 로그인 성공 시 **Access Token(1시간 유효)**과 **Refresh Token(14일 유효, 사용할 때마다 새 토큰으로 교체)**을 발급한다.

**소셜 로그인**
카카오·네이버 계정은 이메일이 아니라 "그 제공자의 그 회원"으로 식별한다. 처음 로그인하는 소셜 계정이면 회원과 계좌 2개를 새로 만들고, 이미 연결된 계정이면 기존 회원으로 로그인만 한다. 같은 이메일의 일반(비밀번호) 회원이 있어도 자동으로 연결하지 않는다 — 계정을 잘못 연결하는 사고를 막기 위한 설계다.

**내 정보 조회·수정**
본인의 이메일·닉네임·가입 방식을 조회한다. 닉네임·비밀번호·이메일을 바꾸려면 먼저 재인증(현재 비밀번호 확인, 또는 소셜 계정 재인증)을 거쳐야 한다. 비밀번호를 바꾸면 다른 기기는 모두 로그아웃되지만 지금 요청한 기기는 새 토큰을 받아 계속 로그인 상태를 유지한다. 이메일을 바꾸면 모든 기기가 로그아웃되어 다시 로그인해야 한다. 새 비밀번호는 8자 이상 100자 이하여야 하며 기존 비밀번호와 달라야 한다.

**비밀번호 재설정 (로그인하지 않은 상태)**
가입된 이메일로 인증번호를 받아 새 비밀번호로 즉시 재설정한다. 인증번호 정책은 이메일 인증과 동일하다(6자리·5분·5회·60초 재발송·1시간 5회·하루 10회). 재설정에 성공하면 모든 기기가 로그아웃된다.

### 4.2 계좌와 자산

가입하면 **코인 계좌와 주식 계좌가 각각 1개씩**, 각 **1,000만원**의 가상 현금과 함께 만들어진다. 두 계좌 사이의 이체는 지원하지 않는다.

계좌 요약은 시장별로 조회하며 현금잔고, 주문에 예약되어 묶인 현금, 보유 종목의 평가금액, 총평가액, 실현손익, 미실현손익을 보여준다. 두 시장을 합친 통합 조회는 제공하지 않는다 — 계좌마다 기준이 달라 합산값이 어느 화면과도 맞지 않기 때문이다.

### 4.3 시장 데이터와 차트

거래 가능한 종목은 **코인 12종, 주식 16종**이다.

**코인 시세**는 빗썸 웹소켓에 상시 연결해 실시간 체결 틱을 받아 그대로 사용한다. 받은 체결 틱은 서버가 진행 중인 1분봉으로 계속 집계해두므로, 캔들 조회는 매번 빗썸에 다시 물어보지 않고 이 값을 먼저 사용한다. 연결이 끊겼거나 그 코인의 시세를 한 번도 받은 적이 없으면 조회와 주문 모두 거부한다. 연결이 살아있고 마지막으로 받은 가격이 있으면, 그 가격을 받은 지 얼마나 지났든 상관없이 항상 사용 가능한 것으로 취급한다.

**주식 시세**는 실제 있었던 과거 거래일의 1분봉 데이터를 매일 **09:00~15:30(KST) 동안 1배속으로 재생**한다. 모든 사용자가 같은 거래일의 같은 분봉을 동시에 보게 되며, 회원마다 다른 것은 자신의 현금·보유수량·거래내역·손익뿐이다. 09:00 첫 1분 동안은 그 거래일 첫 분봉의 시가를 현재가로 쓰고, 그 이후로는 마감이 끝난 가장 최근 분봉의 종가를 현재가·체결가로 사용한다. 그날 재생할 데이터가 준비되지 않으면 그날은 주식 시장을 열지 않는다.

**차트 조회**는 1분봉·일봉·주봉·월봉 4종을 지원하며 한 번에 최대 200개까지 반환한다. 코인 차트는 진행 중인(아직 마감되지 않은) 분봉도 포함해서 보여주지만, 주식 차트는 마감이 끝난 분봉만 보여준다 — 주식은 다음 분봉이 아직 미래이므로 미리 보여줄 수 없기 때문이다.

### 4.4 매매와 체결

**지정가 주문**은 **코인에만 제공**한다. 원하는 목표가로 매수·매도 주문을 걸어두면 즉시 체결되지 않고 대기 상태가 되며, 시세가 갱신될 때마다 조건을 확인해 목표가에 도달하는 즉시(슬리피지 없이 목표가 그대로) 체결한다. 대기 중인 주문은 취소하거나, 목표가·수량을 수정할 수 있다. 지정가 주문을 걸면 매수는 필요한 현금을, 매도는 필요한 수량을 미리 예약해두어 같은 현금·수량으로 이중 주문을 낼 수 없다.

**시장가 주문**은 코인·주식 모두 지원한다. 현재 유효한 가격 하나로 요청한 수량 전체가 즉시 체결되며, 부분 체결은 없다. 같은 요청을 중복으로 보내도 한 번만 체결되도록 보호한다.

**수수료**는 코인 거래금액의 **0.05%**, 주식 거래금액의 **0.015%**이며 원 단위 미만은 버린다. 세금은 적용하지 않는다.

**매도 시 원가 계산**은 먼저 산 것부터 먼저 판다는 원칙(FIFO)을 따른다. 여러 번 나눠 산 종목을 매도하면 그중 가장 먼저 산 물량부터 순서대로 소진되며, 그 원가를 기준으로 실현손익을 계산한다.

**보유 종목의 자동 청산(코인)**은 특정 보유 종목에 손절가·익절가를 걸어두면 코인 시세가 갱신될 때 조건을 만족하는 쪽으로 자동으로 시장가 매도된다.

### 4.5 보유자산과 거래 조회

**보유자산**은 종목별 보유수량·평균매입단가와, 현재가로 계산한 평가금액·미실현손익·수익률을 보여준다. 전량 매도한 종목은 목록에서 사라진다.

**거래내역**은 시장별로 실제 체결된 매수·매도 내역을 조회하며, 매도 건에는 실현손익이 함께 표시된다.

**주문목록**은 시장별로 사용자가 요청한 주문(매수·매도 구분, 종목, 수량, 주문 상태)을 조회한다. 체결가격·수수료 같은 체결 결과는 거래내역에서 확인한다. 코인은 별도로 아직 체결되지 않고 대기 중인 지정가 주문만 모아보는 목록도 제공한다.

목록형 조회는 대부분 한 번에 기본 20개, 최대 100개까지 페이지 단위로 가져온다.

### 4.6 투자 실습 튜토리얼

실제 매매에 들어가기 전에 매수부터 매도, 복기까지 한 사이클을 안내받으며 연습하는 기능이다.

**진행 방식**: 시장(코인 또는 주식)과 연습용 샘플 종목을 고르고 매수한다. 매수 즉시 진입가 기준 **-3% 손절, +5% 익절** 위험 기준이 자동으로 표시되며, 원하면 위험 성향에 맞는 다른 기준으로 바꿀 수 있다(신중형 -2%/+3%, 균형형 -3%/+5%, 여유형 -5%/+8% 중 선택). 코인 종목은 이 기준으로 자동 청산 예약까지 함께 걸린다. 매수 후에는 가격이 움직이는 것을 관찰하다가 직접 매도하고, 마지막으로 이번 실습이 어땠는지 자유롭게 복기를 남기면 완료된다.

**코인 튜토리얼**은 미리 짜인 시나리오를 따라간다 — 상승, 루머로 인한 하락, 속임수성 반등, 확인, 재상승, 급락 등 여러 국면(총 8구간, 가상 시간 120분)을 거치며, 그 국면에서 실제로 무슨 사건이 있었는지는 그 구간이 지나간 뒤에만 공개된다. 매수하기 전까지는 대기 상태로 머무르고, 매수하는 순간부터 다음 국면으로 진행된다. 시간 제한은 없다.

**주식 튜토리얼**은 매수 후 관찰부터 매도까지 **5분**의 시간 제한이 있다.

**완료 보상**: 시장별로 처음 한 번 완료하면 **500만원**을 계좌에 지급한다. 이미 완료한 뒤에도 다시 도전할 수 있지만 보상은 최초 1회만 지급된다.

### 4.7 투자일기

매수·매도 체결 각각에 대해 자유 텍스트로 회고를 1건씩 남길 수 있다. 이미 쓴 회고는 횟수·시점 제한 없이 언제든 수정할 수 있다. 목표가·손절가 같은 구조화된 계획 항목은 없고, 순수하게 자유 서술만 저장한다. 매수·매도 회고를 한 목록에 모아 시장별로 조회할 수 있다. 매도 회고를 수정하면 그 매도에 대한 AI 피드백(4.8절)이 새로 생성된다.

### 4.8 AI 피드백

**변동 원인 서술**: 종목 가격이 크게 움직인 구간에 대해, 그 시점에 있었던 뉴스·공시를 근거로 서술을 만들어 보여준다. 뉴스가 가격 변동의 원인이라고 단정하지 않고, "이 시점에 이런 뉴스가 있었다"는 시간적 동시 발생만 서술한다. 근거가 될 뉴스가 없으면 서술 없이 그 구간을 비워둔다.

**종목 뉴스 요약**과 **개장 전 브리핑**을 종목·시장 단위로 제공한다.

**매도 직후 피드백**: 매도가 체결되면 실현손익·수익률·보유 기간 중 있었던 변동 원인 서술과 함께, 다음 두 가지를 계산해 보여준다.
- **반사실 시뮬레이션** — 실제 판 시점이 아닌 다른 시점(예: 보유 기간 중 최고가·최저가)에 팔았다면 수익률이 어땠을지.
- **집단 비교** — 같은 시점에 같은 상황을 겪은 다른 회원들이 실제로 어떻게 행동했는지의 분포.

매도 회고를 작성하면 그 회고 내용이 AI 서술에 반영된다.

**AI 사용에는 원칙이 있다.** 숫자와 판정(수익률, 변동 여부 등)은 항상 서버가 계산하고, AI는 그 계산 결과를 문장으로 바꾸는 역할만 한다. 특정 종목의 매수·매도를 추천하지 않는다. LLM 호출이 실패하거나 응답이 없으면 서버가 수치로 조립한 문장으로 대신하므로, AI 서비스 장애가 기능 자체를 막지 않는다. 뉴스 기사의 본문은 저장하지 않고 제목·언론사·원문 링크·발행 시각만 남긴다.

### 4.9 랭킹

시장별(코인·주식)로 실현손익 기준 전체 랭킹과 본인 순위를 조회할 수 있다. 매도 체결 이력이 한 번도 없는 회원은 랭킹에서 제외된다. 동점자는 같은 순위로 묶인다. 전체 랭킹은 기본 10명, 최대 50명까지 조회할 수 있다.

### 4.10 커뮤니티

제목과 본문으로 게시물을 작성하고, 특정 종목을 태그하거나, 이미지를 첨부하거나, 본인의 실제 매도 체결 결과를 매매 카드로 첨부할 수 있다. 게시물은 최신순 또는 좋아요가 많은 순으로 조회할 수 있다.

댓글은 대댓글까지 지원한다. 부모 댓글을 삭제해도 그 아래 달린 대댓글은 남아있도록, 내용만 지워진 표시로 바뀐다.

게시물에 좋아요를 표시·취소할 수 있다. 본인이 작성한 게시물·댓글만 수정·삭제할 수 있다.

### 4.11 관심목록

관심 있는 종목을 등록해두고 목록으로 모아보거나 해제할 수 있다.

## 5. 제품 정책

**금액과 원장**
모든 금액·가격·수량 계산에는 부동소수점을 쓰지 않고 정확한 소수 연산을 사용한다. 체결 기록은 한 번 만들어지면 수정하거나 삭제하지 않는 불변 원장이며, 평가손익 같은 값은 저장해두지 않고 조회하는 순간의 최신 시세로 계산한다.

**AI 사용 원칙**
숫자와 판정은 항상 서버가 계산하고 AI는 그것을 사람이 읽을 문장으로 바꾸는 역할만 한다. 특정 종목의 매수·매도를 추천하지 않는다. 뉴스·공시는 가격 변동과 시간적으로 동시에 있었다는 사실만 서술하며 인과관계를 단정하지 않고, 근거가 없으면 서술을 만들지 않는다. 뉴스 기사 본문은 저장하지 않는다.

**데이터 이용과 저작권**
코인 시세는 빗썸이 공개하는 실시간 데이터를 그대로 사용한다. 주식의 과거 시세 데이터는 한국투자증권 Open API로 조회하며, 비상업적 교육 목적의 공개 서비스에서 가공한 과거 데이터로 확인되어 회원에게 표출할 수 있다. 실시간 주식 시세는 제공하지 않으며 항상 과거 거래일 데이터를 재생한다. 이 서비스는 광고·구독·데이터 판매 등으로 수익을 창출하지 않는다. 회원에게 원본 데이터 파일을 다운로드하는 기능이나 원본을 그대로 조회하는 API는 제공하지 않는다. 모든 매매는 가상 자산을 이용한 모의투자이며 실제 주문은 실행되지 않는다.

**시세 공급**
코인 시세는 빗썸 실시간 데이터 하나로, 주식 시세는 과거 데이터 재생 방식 하나로 제공되며, 화면에 보이는 가격과 실제 모의 주문이 체결되는 가격은 각 시장에서 항상 같은 원천에서 나온다.

## 6. 비기능 요구사항

**정합성**
회원가입, 매수, 매도 같은 여러 단계로 이루어진 작업은 전부 성공하거나 전부 실패하도록 원자적으로 처리한다. 동시에 여러 요청이 같은 주문·계좌·보유 종목을 건드릴 때는 항상 같은 순서(주문 → 계좌 → 보유)로 잠금을 걸어 교착 상태를 방지한다.

**장애 대응**
외부 시세 공급이 끊기거나 지연되어도 잘못된 가격으로 체결되는 일이 없도록 한다 — 유효한 가격이 없으면 체결 대신 주문을 거부한다.

**품질 기준**
핵심 시나리오(가입 → 계좌 생성 → 매매 → 조회 → 게시물 작성까지)는 자동화된 테스트로 반복 검증할 수 있어야 하며, 로컬 Docker 환경에서 동일하게 재현할 수 있어야 한다.

## 부록 A. 시스템 개요

- **백엔드**: Spring Boot, Java, 레이어드 아키텍처(controller → service → repository), 기능 도메인별 패키지 구조.
- **데이터 저장**: MySQL(회원·계좌·주문·체결 등 모든 원장 데이터), Redis(코인 실시간 시세, 랭킹 순위, 코인 캔들 캐시 — 전부 유실되어도 MySQL 원장에서 다시 만들 수 있는 파생 데이터).
- **AI 연동**: Spring AI 추상화를 통해 LLM을 호출하며, 서비스 로직은 특정 모델·제공사를 알지 못한다. 기본 제공사는 OpenAI다.
- **외부 연동**: 빗썸(코인 실시간 시세), 한국투자증권 Open API(주식 과거 데이터), 카카오·네이버(소셜 로그인), 뉴스·공시 검색 API.

## 부록 C. 데이터 모델

전체 테이블 구조·연관관계는 [`docs/erd.md`](./erd.md)가 정본이다. 핵심 원장은 다음과 같이 구성된다.

- **투자 실습**: 진행 상태, 완료 기록, 위험 기준 snapshot, 관찰·복기 기록
- **AI 피드백**: 뉴스·공시, 변동 원인 이벤트, 뉴스 요약, 매도 직후 피드백, 집단 비교 통계
- **커뮤니티**: 게시물, 댓글, 좋아요, 첨부 이미지

## 부록 D. 용어 사전

| 용어 | 의미 |
|---|---|
| 시장가 주문 | 현재 유효한 가격으로 즉시 전량 체결되는 주문 |
| 지정가 주문 | 원하는 목표가를 정해두고 그 가격에 도달하면 체결되는 주문(코인 전용) |

| 실현손익 | 실제로 매도가 체결되어 확정된 손익 |
| 미실현손익 | 아직 보유 중인 종목을 현재가로 평가했을 때의 손익 |
| 자동 청산(OCO) | 보유 종목에 손절가·익절가를 걸어두면 조건 충족 시 자동으로 매도되는 예약 |
| 반사실 시뮬레이션 | 실제 매도 시점이 아닌 다른 시점에 팔았다면 수익률이 어땠을지 계산한 결과 |
| 재생(리플레이) | 과거 실제 거래일의 시세 데이터를 시간 순서대로 다시 보여주는 방식 |
