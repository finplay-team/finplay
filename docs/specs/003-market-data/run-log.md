- MKT-008 정정 — **진행 중인 분봉 제외 → 포함** (2026-07-30, 같은 브랜치). 최초 초안은 주식 MKT-002의 "미마감 분봉 노출 금지"를 코인에도 그대로 적용했으나, 사용자가 "코인은 실시간 차트다"라고 지적해 재검토했다. 주식의 제외 규칙은 **과거 거래일 재생 구조**에서 아직 공개되지 않아야 할 분봉이 새는 것을 막고 체결가 계약과 어긋나지 않게 하려는 것이고, 코인은 재생이 아니라 실시간이며 주문도 최신 틱으로 체결되므로 가릴 대상이 자체가 없다. 잘라내면 차트 오른쪽 끝이 최대 59초 늦게 움직여 실시간성만 해친다. 따라서 **코인은 진행 중 분봉을 포함**하고, `StockReplayService`의 공개 컷오프 로직을 코인 경로에 재사용하지 않는다. 같은 캔들 API에서 시장별로 규칙이 다른 것은 의도된 차이이며 "일관성 없음"으로 보고 한쪽에 맞추지 않는다. 함께 명확히 한 것: 빗썸 REST 캔들은 **과거 데이터가 아니라 지금 이 순간까지의 실시간 시장**이다(실측 확인 — 2026-07-30 11:43:06 KST 조회 시 `11:43`(진행 중)·`11:42`·`11:41` 봉 반환). 주식의 `KIS_HISTORICAL`처럼 옛 거래일을 다시 트는 구조가 아니다. WebSocket 틱과 REST 분봉은 같은 지금의 시장을 다른 해상도로 본 것이고, REST가 필요한 이유는 WebSocket이 직전 봉들을 주지 않아 기동 직후 차트가 비기 때문이다. 분 이하 해상도 갱신은 프론트가 SSE 틱으로 마지막 봉을 갱신해 얻으며, **서버는 틱을 분봉으로 집계하지 않고 진행 중 분봉 상태를 메모리에 들고 있지 않는다** — 코인에는 `KisTickAggregator`에 해당하는 컴포넌트를 만들지 않는다.
- 이슈 #20 방향 전환 — SSE 축 제거, 차트 단일 범위로 확정 (2026-07-30, 같은 브랜치). 직전 커밋에서 이슈 #20에 "1축 코인 SSE(기존 범위)"와 "2축 코인 차트(신규)"를 함께 담았으나, 사용자가 명확히 정정했다: 개발 방향 자체가 "코인 실시간 시세를 빗썸에서 연동해 실시간 차트로 보여주는 것"으로 바뀌었고, 아직 구현되지 않은 `/api/cryptos/stream` SSE 방송 엔드포인트(원래 이슈 #20의 전체 범위)는 이제 쓰이지 않을 계획이므로 "만들 필요도 문서에 둘 필요도 없는" 죽은 범위다. 이슈 #20 본문에서 SSE 절을 완전히 제거하고 차트 단일 범위로 재작성했다. 문서 정정 범위를 명확히 하기 위해 그은 경계: **삭제한 것** — 아직 미구현인 공개 SSE 방송(`/api/cryptos/stream`, `CryptoPriceSseController`) 계획을 spec·plan·tasks·prd에서 제거, `/stocks/stream`(#19)만 남김. **건드리지 않은 것** — MKT-003·MKT-004(빗썸 WebSocket→Redis `PriceStore`→`PriceQueryService`)와 그 위에 이미 병합된 코드(이슈 #16, `BithumbFeedClient`·`FakeBithumbFeedClient`·`PriceStore`)는 주문 체결·`PRICE_UNAVAILABLE` 판정의 근거로 그대로 둔다 — 이건 "화면에 실시간 틱을 방송하는 것"과는 다른, 주문 도메인이 계속 필요로 하는 별개의 관심사이기 때문이다. 두 경로(현재가용 Redis/WebSocket ↔ 차트용 REST)는 여전히 완전히 독립이다. 갱신 문서: `docs/prd.md`(§5 API 목록에서 `/api/cryptos/stream` 제거), `docs/specs/003-market-data/{spec,plan,tasks}.md`(SSE 계약을 `/stocks/stream` 전용으로 축소, 코인 SSE 컨트롤러 태스크 삭제), `docs/api-contracts.md`(캔들 절의 실시간 갱신 안내를 "재조회"로 정정). 이슈 #20 본문도 SSE 절 없이 차트 단일 범위로 재작성.
