# Spec: 리뷰 게이트 자동 수정 라운드

## 개요
이슈 트리거 에이전트 하네스(ADR-0013)의 `implement-and-open-pr` job은 PR을 연 뒤 자체 리뷰를 한 번 돌리고, 차단·권장이 모두 0건일 때만 조건부 승인한다. 차단 사항이 하나라도 있으면 그 자리에서 멈춰, 사람이 직접 브랜치에 커밋을 추가하는 것 외에는 고칠 방법이 없다(GitHub 이슈 #292). 같은 job 안에서 차단 사항을 자동으로 한 차례 더 고치고 재검증하는 라운드를 추가한다.

동시에, 같은 job의 "리뷰 결과를 PR에 게시" 스텝이 `structured_output`이 빈 문자열일 때 `if:` 가드와 무관하게 항상 실패하는 확인된 버그(2026-08-09 실행 https://github.com/finplay-team/finplay/actions/runs/31333724172/job/93295980910)를 함께 고친다 — 자동 수정 라운드를 추가하며 같은 파일에 같은 종류의 "리뷰 결과 게시" 스텝을 하나 더 만들게 되므로, 버그를 안은 채 복제하지 않기 위함이다.

## 사용자 시나리오
- 팀원은 이슈에 `@claude N안으로 구현해줘`를 남긴다. 하네스가 PR을 열고 자체 리뷰한다. 리뷰에서 차단 사항이 나오면, 팀원이 개입하지 않아도 하네스가 같은 PR 브랜치에서 그 차단 사항만 한 차례 자동으로 고치고 다시 검증한다.
- 팀원은 PR 코멘트 이력만 보고 자동 수정이 돌았는지, 왜 멈췄는지(차단 해소 / 라운드 소진 / 빌드 실패)를 알 수 있다.
- 자동 수정 라운드가 끝난 뒤에도 차단·권장이 하나라도 남아 있으면 승인은 붙지 않고, 팀원이 직접 리뷰·승인한다(기존 ADR-0013 승인 기준 유지).

## 요구사항
- [ ] 리뷰 라운드 1(PR을 연 직후 자체 리뷰)의 `blocking_count > 0`일 때만, 같은 job·같은 브랜치에서 자동 수정 라운드가 정확히 1회 실행된다.
- [ ] 자동 수정 라운드는 차단(blocking) 사항만 대상으로 한다. 권장(recommended) 사항은 고치지 않는다.
- [ ] 자동 수정 라운드는 "수정 커밋 푸시 → 러너가 직접 `./gradlew build` 재실행 → 독립된 재리뷰 호출 → 재리뷰 결과 PR 코멘트 게시" 순서로 진행된다.
- [ ] 재리뷰를 수행하는 호출은 자동 수정을 수행한 호출과 별도의 claude-code-action 호출이다(자기가 고친 것을 자기가 통과시키지 않는다).
- [ ] 자동 수정 라운드의 PR 코멘트는 "자동 수정 1회차" 헤더로 시작하고, 마지막 줄에 라운드 종료 사유(차단 해소 / 라운드 소진 / 빌드 실패) 중 하나를 명시한다.
- [ ] 자동 수정 라운드가 실행되지 않은 경우(라운드 1에서 이미 차단 0건)에는 기존 흐름과 동일하게 동작한다 — 불필요한 코멘트·호출이 추가되지 않는다.
- [ ] 승인은 최종 라운드(자동 수정 라운드가 돌았으면 그 결과, 아니면 라운드 1 결과) 기준으로 차단 0건·권장 0건일 때만 붙는다(ADR-0013의 승인 기준 자체는 그대로 유지).
- [ ] `implement-and-open-pr` job에 `timeout-minutes`가 명시된다(현재 미설정 상태 — GitHub 기본값 360분에 암묵적으로 의존하는 상태를 없앤다).
- [ ] "리뷰 결과를 PR에 게시" 계열 스텝은 `structured_output`이 빈 문자열이어도 스텝 자체가 실패하지 않는다(2026-08-09 실행에서 확인된 버그의 수정. 자동 수정 라운드의 재리뷰 결과 게시 스텝에도 동일한 방식이 적용된다).

## 비즈니스 규칙
- 자동 수정 라운드는 최대 1회다. 라운드가 끝난 뒤에도 차단이 남아 있으면 더 이상 자동으로 재시도하지 않고 사람에게 넘긴다.
- 자동 수정이 반영해야 하는 지적 범위는 차단뿐이다. 권장까지 자동 수정 대상에 넣지 않는다 — 권장까지 넣으면 리뷰어가 만들어내는 지적만큼 PR 스코프가 원래 이슈를 넘어설 수 있다(이슈 #292 propose-directions 코멘트의 공통 권고).
- 자동 수정 커밋도 러너가 직접 빌드로 검증한다. 에이전트의 "빌드 통과했다"는 자기 보고를 검증 근거로 쓰지 않는다(기존 job의 원칙 유지, `docs/agent-mistakes.md`의 다수 사례와 같은 원칙).
- 무한 루프는 허용하지 않는다 — GitHub Actions의 step은 반복문을 지원하지 않으므로, 라운드 수는 YAML에 고정 스텝으로 언롤되어 구조적으로 상한이 걸린다(런타임 카운터에 의존하지 않는다).
- 사람의 최종 승인·머지 대체는 이번 범위에 포함하지 않는다(ADR-0005의 "자동 머지 금지" 원칙 유지).
- PR 댓글을 통한 재트리거(verify-actor의 PR 댓글 제외 조건 변경)는 이번 범위에 포함하지 않는다.

## 범위 제외
- 재시도 2라운드 이상, 또는 라운드 수를 설정 가능하게 만드는 것.
- 권장(recommended) 사항까지 자동 수정 대상에 포함하는 것.
- 워크플로우 재귀 호출(이슈 #292 propose-directions의 3안) 또는 에이전트 내부 자율 반복(2안) — 채택된 안은 1안(같은 job 안에서 step 언롤)이다.
- PR 댓글로 재수정을 트리거하는 것(verify-actor의 PR 댓글 제외 조건 변경).
- 사람의 최종 승인/머지 자동화.
- 지표 수집 스크립트(하네스 도입 전/후 비교) — `docs/harness-roadmap.md`의 별도 미착수 항목이며 이번 스코프가 아니다.

## 완료 조건
- [ ] 차단 사항이 있는 self-review 이후 같은 PR 브랜치에서 자동 수정 커밋이 추가되는 것을 실제 이슈로 검증한다.
- [ ] 무한 루프 방지 장치(구조적 step 언롤 + `timeout-minutes`)가 워크플로우에 존재한다.
- [ ] `docs/harness-roadmap.md`의 관련 항목이 갱신된다.
- [ ] `docs/adr/0016-*.md`가 작성되고, ADR-0013의 "조건부 승인" 절을 대체(superseded)로 표시한다.
- [ ] "리뷰 결과를 PR에 게시" 계열 스텝이 `structured_output` 빈 값에서도 실패하지 않는 것을 확인한다(재현 가능한 방식의 로컬/드라이런 검증 또는 실제 이슈 실행으로).
