# Spec: 튜토리얼 전용 샘플 종목·항시 시세·매도 단계·5분 제한 (Sandbox 실습 확장)

> 상태: 2026-08-11 spec·plan 확정. **구현 완료**(이슈 #339, PR #341).
>
> **이 spec은 `026-market-order-practice-tutorial`을 대체하지 않고 확장(amend)한다.** `026`이 정의한
> `favorite → intention → buyTrade → holding` 2단계 chain 해석, 참조 가격선 계산, evidence A/B 판정, 불변 완료
> 원칙은 전부 변경 없이 그대로 상속한다. 이 spec이 바꾸는 것은 (1) 항상 매매·관찰 가능한 샘플 종목의 존재,
> (2) `GET /api/education/practice`의 3단계 응답 모델을 4단계로 확장, (3) 매수~매도(또는 만료)의 5분 제한이다.
> `026`의 완료 key(`INVESTMENT_PRACTICE_V1`/`COIN_PRACTICE_V1`)와 `practice_completions` 불변 완료 원칙은
> 그대로 유지되며, 기존에 이미 완료된 사용자의 완료 상태는 이 변경으로 회귀하지 않는다(`026` 원칙 상속).
>
> **`030-coin-practice-price-runtime`과는 병행이다, 대체가 아니다.** `030`의 코인 가상 가격 세션은 지정가
> 주문·세션 tick·holding 관찰의 가격원을 다루며, 이 spec의 샘플 종목·항시 시세는 그와 별개로 시장가 매매
> (STOCK·CRYPTO 공통) 경로에서 "실제 시세 피드가 비었거나 장이 닫혀 있어도 튜토리얼이 항상 진행 가능하다"는
> 더 근본적인 문제를 다룬다. 코인 샘플 종목에 대해 사용자가 `030`의 지정가 세션 경로를 쓰는 것도 막지
> 않는다 — 샘플 종목이라고 지정가를 금지할 이유가 없으며, 이 spec은 시장가 경로가 항상 성립하는 것만 보장한다.

## 개요

`026`의 3단계 실습(즐겨찾기 → 의도 기록·매수 → 관찰·복기)은 실제 종목과 실제 시세 피드(주식 재생세션,
빗썸 `PriceStore`)에 의존한다. 장 시간 밖이거나 시세 피드가 비어 있으면 `PriceQueryService`가
`PRICE_UNAVAILABLE`을 던져 튜토리얼 자체가 막힌다(프론트엔드 수동 테스트에서 실제로 재현, 이슈 #339).

이 spec은 실제 종목과 완전히 분리된 **튜토리얼 전용 샘플 종목**을 시장별로 3개씩 신설해, 실제 시세 피드
상태·장 시간과 무관하게 항상 유효한 가격을 반환하도록 한다. 그 위에 실습 4단계째로 **매도**를 추가하고,
매수~매도(또는 만료)까지 **5분 제한**을 도입한다. 실제 거래(`/api/orders` 일반 매매), 커뮤니티, 랭킹,
포트폴리오 등 다른 기능의 종목·시세·장시간 규칙은 전혀 건드리지 않는다.

## 사용자 시나리오

- 로그인 사용자는 종목 목록(`GET /api/instruments?market=`)에서 시장별로 노출된 3개의 샘플 종목을 볼 수
  있다. 그중 1개(`tradable=true`)만 실제로 즐겨찾기·매수·매도할 수 있고, 나머지 2개는 목록에 보이지만
  선택할 수 없다.
- 사용자는 이 샘플 종목으로 즐겨찾기 → 의도 기록·매수(2단계, `026`과 동일)를 진행할 때, 장 시간이나
  실제 시세 피드 상태와 무관하게 항상 가격을 조회하고 매수를 체결할 수 있다.
- 사용자는 매수 체결 이후 5분 안에 가격을 관찰하며 견디고(3단계), 실제 매도 주문(`POST /api/orders`,
  `side=SELL`, 시장가)을 실행한 뒤 그 매도와 연결해 복기를 저장(4단계, 신규)한다.
- 5분이 지날 때까지 매도하지 않으면 그 매수 chain은 만료되어 4단계를 완료할 수 없고, 사용자는 같은
  종목을 다시 매수해 새 chain으로 재도전해야 한다.

## 요구사항

- [x] SANDBOX-001: 주식·코인 시장마다 실제 종목이 아닌 샘플 종목 3개를 신설한다. 시장별 1번째만
  `tradable=true`, 나머지 2개는 `tradable=false`로 목록에는 노출되되 즐겨찾기·매수 대상에서 배제된다
  (`026`이 이미 상속한 "존재하지 않거나 비활성 종목" 배제 규칙을 그대로 적용받는다 — 별도 배제 로직을
  새로 만들지 않는다).
- [x] SANDBOX-002: 샘플 종목은 실제 시세 피드 연결 상태·장 시간과 무관하게 항상 유효한 가격을 반환한다.
  이 종목에 대한 어떤 가격 조회도 `PRICE_UNAVAILABLE`을 던지지 않는다.
- [x] SANDBOX-003: 주식 샘플 종목은 09:00~15:30 개장 게이트, 영업일 판정, 재생세션 준비 여부를 전혀
  적용받지 않고 항상 매매 가능(`MARKET_CLOSED`가 나지 않음)으로 취급된다.
- [x] SANDBOX-004: 샘플 종목의 가격은 완전히 고정된 값이 아니라 시간에 따라 결정적으로(같은 공식,
  저장 상태 없음) 소폭 변동한다 — `026`의 3단계 evidence A(경계 접근)가 샘플 종목에서도 원칙적으로
  도달 가능해야 하기 때문이다(아래 "가격 알고리즘" 참고).
- [x] SANDBOX-005: `GET /api/education/practice?market=`의 응답 단계 모델은 **해석된 chain의 종목이
  샘플 종목(`is_tutorial_sample=true`)일 때만** 3단계에서 4단계로 확장된다 — 1즐겨찾기, 2의도 기록·매수,
  3견디기/관찰(evidence A/B, `026`과 동일 판정), 4매도·복기(신규, evidence는 매도 체결과 자유 복기 둘
  다 필요). **실제 종목 chain은 `026`의 3단계 응답을 그대로 유지한다** — `steps` 배열 길이가 chain의
  종목 종류에 따라 3 또는 4로 달라진다(프론트엔드는 배열 길이로 분기). 이미 완료된 `practice_completions`
  행의 과거 완료 상태는 회귀하지 않는다.
- [x] SANDBOX-006: 4단계(매도·복기)의 매도 evidence는 기존 `POST /api/orders`(`side=SELL`,
  `orderType=MARKET`)로 만들어진 실제 `FILLED` 체결이다. 튜토리얼 전용 매도 엔드포인트를 신설하지 않는다.
  이 4단계 자체가 샘플 종목 chain에만 존재하므로, 매도 evidence 판정도 샘플 종목 chain에만 적용된다.
- [x] SANDBOX-007: (샘플 종목 chain 한정) 매수 체결(`buyTrade.executedAt`)부터 5분 이내에 그 chain의
  매도 체결이 없으면 그 chain은 만료된다. 만료된 chain은 4단계를 완료할 수 없고, 사용자가 같은 종목을
  다시 매수해 만든 새 chain(새 `buyTrade`)만 4단계 대상이 될 수 있다. 실제 종목 chain에는 이 만료 개념이
  없다(4단계 자체가 없으므로).
- [x] SANDBOX-008: `POST /api/education/practice/holding-reflections`(기존 URL 재사용)는 **샘플 종목
  chain에 대해서만** evidence A/B에 더해 유효한(5분 이내) 매도 체결을 요구한다. 매도 체결이 없으면 409
  `PRACTICE_EVIDENCE_MISSING`, chain이 만료됐으면 409 `PRACTICE_SANDBOX_TIME_EXPIRED`다. 실제 종목
  chain은 `026`의 기존 전제조건(evidence A/B만)을 그대로 유지한다.
- [x] SANDBOX-009: 이 spec은 실제 종목·실제 시세·장시간 규칙, `030`의 코인 가상 가격 세션·지정가 경로를
  변경하지 않는다.

## 비즈니스 규칙

- 샘플 종목의 `tradable=true`는 시장당 정확히 1개다. 나머지 2개는 상세 시세·주문 경로 대상이 아니지만
  목록 응답(`GET /api/instruments`)에는 그대로 노출된다.
- 샘플 종목 여부는 종목의 불변 속성이다 — 이미 만들어진 샘플 종목을 실제 종목으로, 또는 그 반대로
  전환하는 기능은 없다.
- 5분 제한은 실제 주문 접수 자체를 막지 않는다 — 사용자가 5분이 지난 뒤 매도해도 그 매도 주문은 정상
  체결된다(실제 자산·수량이 걸린 거래이므로 강제로 거부할 근거가 없다). 5분 제한은 오직 **그 매도를
  4단계 evidence로 인정할지**를 결정하는 튜토리얼 판정 로직에서만 적용된다.
- 만료된 chain은 재시도 가능하다 — `026`이 이미 "완성 chain이 여러 개면 우선순위 규칙으로 하나를
  고른다"는 원칙을 갖고 있으므로, 만료된 chain은 그 우선순위 계산에서 자연히 배제되고 사용자는 새
  intention 없이(기존 intention 재사용, `026`과 동일) 새로 매수만 하면 된다.
- 완료(`practice_completions`) 이후에는 chain 만료·재매수·재복기 여부와 무관하게 완료 상태가
  회귀하지 않는다(`026` 원칙 상속, 변경 없음).

## 범위 제외

- 실제 거래(`/api/orders` 일반 매매)의 종목·시세·장시간 규칙 변경 — 대상 아님.
- 3차 MVP OCO 경로 — 대상 아님.
- 튜토리얼 전용 매도 엔드포인트 신설 — 기존 `POST /api/orders`를 그대로 재사용한다(SANDBOX-006).
- 5분 만료 시 서버가 매도 주문 자체를 거부하는 것 — 하지 않는다(위 비즈니스 규칙 참고). 서버는 evidence
  판정에서만 만료를 반영한다.
- 샘플 종목의 실시간 시세 SSE·캔들 API 지원 — 이 spec은 가격 API(`PriceQueryService.getPrice`/
  `getOrderExecutionPrice`)만 다룬다. 캔들·SSE는 후속 이슈로 남긴다(비어 있어도 프론트엔드 실습 흐름에
  필수가 아니므로 이 spec에서 다루지 않는다).
- 프론트엔드(finplay-frontend) 구현 — `plan.md` "프론트엔드 영향" 절에 계약만 요약한다.
