# Tasks: 캔들 조회 기간 확장 — 일봉/주봉/월봉 (1d · 1w · 1M)

> spec: `./spec.md` / plan: `./plan.md` / 이슈 #143
> 신규 Flyway 마이그레이션·신규 테이블·신규 Redis 키를 만들지 않는다. `interval=1m` 경로는 어느 항목에서도 동작이 바뀌면 안 된다.

- [x] **① `interval` 4값 확장과 배관** — `CandleInterval`에 `ONE_DAY("1d")`·`ONE_WEEK("1w")`·`ONE_MONTH("1M")` 추가(대소문자 구분 유지 이유를 주석으로 남김, `equalsIgnoreCase` 금지), 오류 메시지를 4개 값 나열로 갱신, 집계 여부 판정 도우미 추가. `CandleQueryService`가 파싱한 `CandleInterval`을 버리지 않고 아래로 전달하도록 변경하고 `from > to` 판정을 분기(주식 `1m`=시각 비교 유지, 주식 집계=날짜 비교, 코인=`LocalDateTime` 전체 비교). `StockPriceProvider.getCandles`·`CryptoCandleProvider.getCandles` 시그니처에 `CandleInterval` 추가하고 구현체(`KisHistoricalReplayPriceProvider`·`LocalForcedOpenStockPriceProvider`·`BithumbRestCandleProvider`·`FakeCryptoCandleProvider`)를 컴파일 가능하게 맞춘다 — 이 단계에서 집계·일봉 위임은 아직 없고 `1m` 외 주식·코인 요청은 빈 목록으로 둔다. (+ 단위: `CandleInterval` 4값 허용·`1M`≠`1m`·`1D`·`1W`·`5m`·빈 문자열 400, `CandleQueryService` interval별 `from > to` 기준과 검증 순서 / `@WebMvcTest`: `1d`·`1w`·`1M`이 더 이상 400이 아님, 잘못된 `interval` 400, 401 유지 / 회귀: 기존 `1m` 테스트 전부 통과)

- [x] **② 주식 집계기 `StockCandleAggregator`** — `market/service`에 Spring 의존이 없는 순수 클래스로 신규 작성. 공개된 분봉 목록(`(tradingDate, candleTime)` 오름차순)과 `CandleInterval`을 받아 버킷 목록을 반환한다. 버킷 키는 `1d`=`tradingDate`, `1w`=`tradingDate.with(DayOfWeek.MONDAY)`, `1M`=`tradingDate.withDayOfMonth(1)`. 값은 `open`=최초 분봉 open, `high`=max, `low`=min, `close`=최종 분봉 close, `volume`=합. 출력은 `new StockCandleDto(버킷시작일, LocalTime.MIDNIGHT, ...)`로 기존 DTO를 재사용한다(신규 DTO 금지). 분봉이 0개인 버킷은 만들지 않고 빈 구간을 채우지 않는다. (+ 단위 테스트: 버킷 키 3종, 여러 거래일이 한 주·한 달로 묶임, 주 시작이 월요일임(일·토 아님), 월 말일→다음달 경계, OHLCV 산출, 거래일 없는 주·월이 결과에 없음, `sourceTime`이 버킷시작일 `T00:00`)

- [x] **③ 공개 상한을 지키는 집계 조회** — `StockCandleRepository`에 `findByInstrumentIdAndTradingDateBetweenOrderByTradingDateAscCandleTimeAsc` 파생 쿼리 추가(기존 메서드 6개는 유지, 인덱스 추가 없음). `StockReplayService`에 `getRevealedAggregatedCandles(instrumentId, interval, fromDate, toDate)` 추가 — 기존 `getRevealedCandles`는 손대지 않는다. `READY` 세션 없으면 빈 목록, `rangeEnd`는 재생거래일을 넘지 않게 클램프, `from` 생략 시 `lookbackFloor`(`1d` 400일 / `1w` 200주 / `1M` 200개월) 적용, **조회를 2회로 분리**(과거 거래일 구간 + 재생거래일의 컷오프 이하 분봉)해 미공개 분봉을 애초에 읽지 않는다, 결과 200개 초과 시 최신 200개만 남긴다. `KisHistoricalReplayPriceProvider`가 `interval`에 따라 이 메서드로 위임한다. (+ 단위: 세션 없음→빈 목록, 09:01 이전 재생거래일 버킷 미생성, 09:01 이후 컷오프까지만 반영된 진행 중 버킷, 재생거래일 이후 `trading_date` 제외, 200 캡, lookback floor / `@DataJpaTest`: 신규 쿼리 경계 포함·정렬·타 종목 미포함)

- [ ] **④ 코인 일/주/월봉 위임** — `BithumbRestCandleProvider`에 `interval`별 엔드포인트 분기(`/v1/candles/days`·`/weeks`·`/months`, `1m`은 기존 `minutes/1` 유지)와 `count` 단위별 산출(일=DAYS, 주=월요일 정렬 후 WEEKS, 월=1일 정렬 후 MONTHS, 각각 `+1` 후 200 캡) 추가. `to`의 KST→UTC 변환·정렬 반전·필드 매핑·null 검사·타임아웃·502 경로는 기존 로직을 공유하고 `BithumbCandleItem` 레코드를 그대로 재사용한다(신규 레코드 금지, `convertingPriceUnit` 미사용). `candle_date_time_kst`를 보정 없이 `sourceTime`으로 매핑한다. `FakeCryptoCandleProvider`는 interval별 시드를 지원하되 기존 `setCandles(symbol, candles)`는 `1m` 시드로 남긴다. (+ 단위 `MockRestServiceServer`: interval별 호출 URL, `count` 단위별 계산·200 캡, `to` UTC 변환, 내림차순→오름차순 반전, 일/주/월봉 전용 필드가 섞인 JSON 파싱 성공, `trade_price`→`close`·`candle_acc_trade_volume`→`volume`, 실패 3종 502·빈 배열 아님, 저장·캐시 없음)

- [ ] **⑤ 통합 테스트와 문서 동기화** — Testcontainers 통합 테스트로 서로 다른 3개 이상 거래일(같은 주·다른 주·다른 달이 섞이게)의 분봉과 `READY` 재생세션을 시드해 `1d`·`1w`·`1M` 응답의 개수·`sourceTime`·OHLCV를 검증하고, **같은 테스트에서 `interval=1m` 응답이 기존 계약 그대로임을 확인한다**(회귀). 코인은 `FakeCryptoCandleProvider` interval 시드로 200 확인. 이어서 `docs/api-routes.md`(라우트 표의 `interval` 표기·설명)와 `docs/api-contracts.md`(요청·응답·오류 계약, 주식 집계 규칙과 코인 위임 규칙, **주식과 코인의 버킷 경계 정의가 다를 수 있다는 명시**)를 같은 커밋에서 갱신한다. `docs/specs/003-market-data`의 이력 표시가 이 spec과 상충하지 않는지 확인한다. 마지막에 `./gradlew spotlessApply && ./gradlew build` 통과.
