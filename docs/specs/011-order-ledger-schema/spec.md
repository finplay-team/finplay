# Spec: 주문·체결 원장 스키마 구축

> 근거: GitHub 이슈 #12. API 없음 — 데이터 구조 선행 작업.
> 후속 이슈(#13 매수, #21 주문 목록, #22 중복 요청 방지, #41 매도)가 이 스키마 위에서 구현된다.

## 개요

매매는 "샀다, 팔았다"로 끝나지 않는다. 무엇을 요청했는지(주문), 실제로 얼마에 체결됐는지(체결), 지금 얼마나 들고 있는지(보유), 나중에 팔 때 어느 매수분이 팔린 것인지(매수 lot과 배분)까지 남아야 실현손익을 말할 수 있다. 이 다섯 가지 기록이 지금 하나도 없다. 매수(#13)·중복 요청 방지(#22)·매도(#41)·주문 목록(#21)이 전부 같은 테이블 위에서 돌아가므로, 각 브랜치가 필요할 때마다 테이블을 추가해 마이그레이션이 서로 부딪히지 않도록(ADR-0004: 머지된 마이그레이션 수정 금지) 다섯 테이블을 한 번에 만들고 시작한다.

## 사용자 시나리오

- (API 없음 — 이 spec은 후속 기능이 사용할 데이터 구조만 만든다.)
- 이후 매수 기능(#13)이 새 마이그레이션 없이 `orders`·`trades`·`holdings`·`holding_lots`에 데이터를 쓸 수 있다.
- 이후 매도 기능(#41)이 새 마이그레이션 없이 `trade_allocations`에 FIFO 배분을 기록할 수 있다.
- 이후 중복 요청 방지 기능(#22)이 새 마이그레이션 없이 `orders`의 멱등키·요청 해시 컬럼을 사용할 수 있다.

## 요구사항

- [ ] 마이그레이션 한 개(V10)로 `orders`, `trades`, `holdings`, `holding_lots`, `trade_allocations` 다섯 테이블을 생성한다.
- [ ] `orders`는 멱등키 컬럼과 요청 해시 컬럼을 포함하고 `UNIQUE(user_id, idempotency_key)`를 갖는다 (#22 선행조건).
- [ ] `trade_allocations`도 이 마이그레이션에서 만든다 (#41 선행조건).
- [ ] `holdings`는 `UNIQUE(account_id, instrument_id)`를 갖는다.
- [ ] 금액(거래금액·수수료·실현손익 등)은 원 단위 `BIGINT`로, 코인 수량은 `DECIMAL(30,8)`로 둔다 — `double`·`float` 금지 (PRD C-003).
- [ ] 엔티티 5종(Order, Trade, Holding, HoldingLot, TradeAllocation)과 주문 구분(`OrderSide`)·주문 유형(`OrderType`)·주문 상태(`OrderStatus`) 열거형을 추가한다.
- [ ] 엔티티는 기존 `Account`·`Instrument`와 같은 방식 — `@Getter` + `@NoArgsConstructor(access = PROTECTED)`, 정적 팩토리(`create`/`of`), setter 없음 — 을 따른다.
- [ ] Repository 5종은 `JpaRepository` 상속만 둔다. 조회 쿼리 메서드는 각 기능 이슈(#13, #21, #22, #41)에서 추가한다.

## 비즈니스 규칙

- 체결(`trades`) 기록은 수정·삭제하지 않는 불변 원장이다 (PRD C-003).
- 매수 체결 1건은 매수 lot(`holding_lots`) 1건을 만든다 (최초수량 = 잔여수량 = 체결수량).
- 매도는 FIFO로 미소진 매수 lot을 차감하며, 하나의 매도가 여러 lot을 소비할 수 있고 각 소비는 `trade_allocations`에 별도 행으로 남는다.
- lot의 잔여수량은 그 lot에 대한 배분수량 합계와 항상 일치해야 한다(최초수량 - 배분수량 합 = 잔여수량) — 이 불변식은 후속 매도 이슈(#41)의 구현 책임이며, 이 spec은 이를 표현할 수 있는 컬럼만 제공한다.
- 다른 시장(주식·코인) 계좌와 종목의 조합은 애초에 성립하지 않아야 한다 — 이는 서비스 계층 검증 대상이며(#13, #41), 이 스키마는 계좌·종목을 각각 FK로만 참조한다.

## 범위 제외

- 주문 생성·조회 API 일체 (#13, #21, #22, #41에서 구현).
- 포트폴리오·체결내역 조회용 인덱스 튜닝.
- 주문 취소·정정·지정가 관련 컬럼 (1차 제외).
- 서비스·컨트롤러 계층, 비즈니스 로직 구현 (엔티티·Repository·마이그레이션만).
