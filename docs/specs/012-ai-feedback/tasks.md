# Tasks: 012 AI 피드백 — 이슈 #147 (LLM 서술 생성·후검증·템플릿 폴백)

> **이 문서는 이슈 #147의 범위만 담는다.** spec 012 전체(이슈 8개)의 분할은 `./plan.md`가 정본이고, 값·규칙은 `./spec.md` §확정값이 정본이다. 여기에 값을 다시 적지 않는다.
>
> 항목 하나 = implementer 1회 투입 = 커밋 1개. 테스트 레벨은 ADR-0003을 따른다 — **이 이슈에는 엔티티·리포지토리·컨트롤러가 없으므로 전부 단위 테스트**이고, 컨텍스트 기동만 기존 `@SpringBootTest`로 확인한다.

## 이 이슈 전체에 걸리는 제약

- **실제 API를 호출하는 자동 테스트를 만들지 않는다** (ADR-0011). 검증은 Fake `NarrativeGenerator`로만 한다. `.env`에 실제 `OPENAI_API_KEY`가 들어 있어도 테스트가 그 값을 읽는 경로를 만들지 않는다.
- **엔티티·응답 DTO에 의존하지 않는다.** `market_news_items`·`price_move_events` 엔티티는 #2가, 카드·매도 회고 도메인은 #4·#6이, 응답 DTO는 #4·#5·#6이 만든다. **#1이 정의하는 입력 타입에 #4·#6이 묶이므로**(뒤 이슈가 이 형태에 맞춰 조립하게 된다) 입력은 전부 **#1이 자체 정의한 record**로 받는다.
- 내부 전달용 record는 `feedback/service/`에 `~Dto` 접미사로 둔다 (`docs/conventions.md`, 기존 `StockCandleDto`·`SellAllocationDto` 선례). 응답 DTO가 아니므로 `dto/response/`에 두지 않는다.
- Spring AI 스타터 추가와 키 없는 기동 보장은 **스파이크 커밋 `d311b87`에서 끝났다** (`build.gradle`, `application.yml`의 `spring.ai.*`). 아래 항목은 그 위에서 시작한다.
- `.env.example`·`compose.deploy.yaml`의 환경변수 4종 추가는 **3번 이슈 조건**이다 (`plan.md` §완료 조건 배정). 여기서 하지 않는다.

## 작업 항목

- [x] **1. `feedback.llm.*` 프로퍼티 바인딩과 기본값**

  §C-7의 `feedback.llm` 블록 5개 값을 `@ConfigurationProperties(prefix = "feedback.llm")` record로 바인딩하고 `application.yml`에 기본값을 둔다. 위치는 `feedback/config/`, 선례는 `market/config/KisProperties`(record + `@DefaultValue`)다. **§C-7의 나머지 블록(`detection`·`news`·`crypto`·`instruments`)은 뒤 이슈 소유이므로 여기서 만들지 않는다.**
  - 값은 코드에 상수로 박지 않는다 (ADR-0011).
  - 검증 — 단위 테스트로 `application.yml` 없이 바인딩 기본값이 §C-7과 같은지 단정한다. 설정을 하나도 주지 않아도 기동하는지는 기존 `@SpringBootTest`가 이미 돌고 있으므로 별도 케이스를 만들지 않는다.

- [x] **2. `NarrativeGenerator` 인터페이스와 OpenAI 구현, Fake 구현**

  인터페이스는 **완성된 프롬프트 문자열(시스템·사용자)만 받아** 성공 문자열 또는 실패를 반환한다(§C-6). 프롬프트 조립·후검증·재시도를 여기 넣지 않는다. Spring AI `ChatClient` 구현과, 테스트용 Fake 구현을 함께 만든다.
  - **키가 없으면 호출 자체를 하지 않고 즉시 실패를 반환한다** (§실패 처리). `application.yml`의 자리표시자 기본값(`not-configured`)이 곧 "키 없음"이므로, **그 리터럴을 판정하는 자리는 한 곳뿐이어야 한다.**
  - 타임아웃·최대 토큰·모델은 1번의 프로퍼티에서 받는다.
  - 실패는 예외를 위로 던지지 않는다 — 호출부가 템플릿으로 폴백할 수 있는 반환값이어야 한다 (ADR-0011).
  - 검증 — 단위 테스트. ① 키가 없으면 `ChatClient`를 **한 번도 호출하지 않고** 실패를 반환한다(mock 호출 횟수 0). ② 호출이 예외를 던져도 예외가 새어 나가지 않고 실패 반환이 된다. ③ 키 없는 환경에서 기존 `@SpringBootTest`가 그대로 통과한다(스파이크에서 확인한 기동 회귀 방지).

- [x] **3. `NarrativePromptBuilder` — 입력 record와 프롬프트 6종**

  §LLM 프롬프트의 시스템 프롬프트 1종 + 파트별 사용자 프롬프트 4종(변동 카드 · 매도 회고 · 종목 뉴스 요약 · 개장 전 브리핑) + 재생성 프롬프트 1종을 조립한다. 입력 record 4종도 여기서 정의한다(위 §제약).
  - 요약 프롬프트는 **범위 줄을 입력으로 받는다** — `PRE_MARKET`·`FULL`·`ROLLING_24H`가 같은 조립 경로에서 갈린다(§LLM 프롬프트). 범위를 프롬프트에 넣지 않으면 `PRE_MARKET` 생성에 `FULL` 기사가 섞여도 모델이 알 수 없다.
  - 재생성 프롬프트는 **적발된 표현 목록을 인자로 받아 문자열에 그대로 넣는다** (§후검증의 확정 문구).
  - 문장 수 지시는 파트별로 다르다 (§LLM 프롬프트 마지막 줄).
  - 검증 — 단위 테스트. 조립된 문자열에 ① 파트별 문장 수 지시, ② 요약의 범위 줄이 범위별로 다르게, ③ 재생성 프롬프트에 **적발 표현이 실제로 포함**되는지를 단정한다(§완료 조건 문구 7번째). 외부 의존이 없으므로 mock이 필요 없다.

- [x] **4. `NarrativeValidator` — 금지 표현 5줄과 파트별 적용**

  §후검증의 5줄을 정규식으로 검사하고, **적발된 표현 목록을 담은 결과 타입**을 반환한다. 파트별 적용은 §후검증의 표를 그대로 따른다 — 카드·매도 회고는 5줄 전부, 요약·브리핑은 `판단·훈수`를 뺀 4줄.
  - **판정만 한다.** 적발 후 무엇으로 대체할지(템플릿 · 재생성 · `NONE`)는 6번의 `NarrativeService`가 정한다. 이 클래스는 `NarrativeGenerator`를 주입받지 않는다 — 이유는 §C-6에 있다.
  - **목록을 임의로 넓히거나 좁히지 않는다** (§후검증). 통과·차단의 경계가 완료 조건으로 못 박혀 있다.
  - `narrative_source` 값(`LLM`·`TEMPLATE`·`NONE`)을 표현할 enum을 여기서 정의한다 — #1의 완료 조건이 "서술 없음 + `NONE`"을 단정해야 하는데 엔티티는 #2에 있다. **#2는 이 enum을 `@Enumerated(STRING)`으로 재사용한다**(§C-8).
  - 검증 — 단위 테스트. §완료 조건 문구 1~5번째를 그대로 케이스로 옮긴다. ① 5줄이 파트별 표대로 동작 ② `버티`·`놓치`·`았다면`이 매도 회고에서 적발 ③ 요약의 `기회를`은 통과 ④ 요약의 `하세요`는 적발 ⑤ `매도했습니다`는 통과.

- [x] **5. `NarrativeTemplateBuilder` — 템플릿 문장 3종**

  §템플릿 문장의 장중 카드·시가 갭·매도 회고 3종을 수치로 조립한다. 입력은 3번이 정의한 record를 재사용하거나 필요한 필드만 받는 자체 record로 하고, **엔티티를 받지 않는다.**
  - **문장을 만들기만 한다.** 언제 템플릿으로 갈아탈지 판정하는 것은 6번의 `NarrativeService`다. 이 클래스는 `NarrativeGenerator`·`NarrativeValidator`를 주입받지 않는다.
  - 요약·브리핑에는 템플릿이 없다 — 이 클래스에 만들지 않는다 (§템플릿 문장).
  - 수치 포맷(부호·소수 자릿수·천 단위)이 표의 형식과 어긋나지 않게 한다.
  - 검증 — 단위 테스트로 고정 입력의 출력 문자열을 그대로 단정한다. **조립된 템플릿 문장이 4번의 후검증을 통과하는지도 함께 단정한다** — 폴백 문장이 금지 표현에 걸리면 폴백 자체가 성립하지 않는다.

- [x] **6. `NarrativeService` — 파트별 서술 확정 경로 (1단계·2단계)**

  앞의 넷을 주입받아 §후검증의 흐름을 실행하는 **이 도메인의 유일한 서술 진입점**을 만든다. 뒤 이슈(#4·#5·#6)의 조회·배치 서비스는 이것 하나만 주입하고 생성기·검증기를 직접 알지 않는다.
  - **요약·브리핑 (2단계)** — 1차 생성 → 통과면 `LLM`, 걸리면 **적발 표현을 넣은 재생성 프롬프트로 1회만** 재생성 → 통과면 `LLM`, 또 걸리면 **서술 없음 + `NONE`**.
  - **카드·매도 회고 (1단계)** — 생성 → 통과면 `LLM`, 걸리거나 호출이 실패하면 **곧바로 템플릿**(`TEMPLATE`). 재시도하지 않는다 — 대체할 문장이 있으므로 재시도할 이유가 없다(§후검증).
  - `NarrativeValidator`에 두지 않은 이유는 §C-6에 적어 뒀다(템플릿 폴백은 국소적 선택이지만 재생성은 프로바이더를 다시 부르는 다른 층위다). **여기서 클래스를 더 늘리지 않는다** — 필요하면 §C-6을 먼저 고친다 (CLAUDE.md 규칙 1·2).
  - 재생성 횟수는 §C-7의 `max-regeneration`을 읽는다. 상수로 박으면 완료 조건이 무의미해진다.
  - **이 이슈가 단정하는 범위는 반환 타입에서 "서술 없음 + `NONE`"까지다.** 상태값 `UNAVAILABLE` 매핑과 `items` 채움은 엔티티·응답 DTO가 필요해 **#5 소유**다(`plan.md` §완료 조건 배정).
  - 검증 — 단위 테스트. Fake `NarrativeGenerator`로 ① 1차 적발 → 2차 통과 경로가 살아난다(§완료 조건 문구 6번째, "기사 제목에 전망") ② 2차도 적발되면 서술 없음 + `NONE` ③ 생성 호출 횟수가 `max-regeneration + 1`을 넘지 않는다 ④ 2차 프롬프트에 1차 적발 표현이 들어 있다 ⑤ **카드·매도 회고는 적발 시 재생성 없이(호출 1회) 템플릿 문장 + `TEMPLATE`이 된다**(§완료 조건 문구 2번째) ⑥ 키가 없어 생성이 실패해도 카드·매도 회고는 템플릿으로 200 경로가 유지된다.
