# Tasks: 012 AI 피드백 — 이슈 #167 (뉴스·공시 수집 파이프라인)

> **이 문서는 이슈 #167의 범위만 담는다.** spec 012 전체(이슈 8개)의 분할은 `./plan.md`가 정본이고, 값·규칙은 `./spec.md` §확정값이 정본이다. 여기에 값을 다시 적지 않는다 — 크론과 주기는 §C-1, 구간은 §C-2, 공시 날짜 판정은 §C-3, 패키지 배치와 클래스 이름은 §C-6, 설정 방침과 종목 수는 §C-7, 컬럼 타입은 §C-8, 엔드포인트·헤더·제약·환경변수는 §외부 API 호출 상세, 실패 시 대응은 §실패 처리다.
>
> 항목 하나 = implementer 1회 투입 = 커밋 1개. 테스트 레벨은 ADR-0003을 따른다 — **이 이슈에는 컨트롤러가 없어 `@WebMvcTest`가 없다.** 질의어·필터는 외부 의존이 없어 순수 단위, 외부 호출 구현은 `MockRestServiceServer`로 응답을 고정한 단위(`KisHistoricalCandleClientImplTest` 선례), 저장·중복 판정은 `@DataJpaTest`, 수집 종단은 고정 `Clock` + Testcontainers 통합이다.

## 이 이슈 전체에 걸리는 제약

- **여기서 값을 새로 정하지 않는다.** 크론·주기·구간·종목 수·엔드포인트가 필요하면 위 참조를 읽는다. spec에 없는 값이 필요해 보이면 코드가 아니라 `spec.md`를 먼저 고친다 (CLAUDE.md 규칙 1·2).
- **#160이 만든 것을 재사용한다.** `market_news_items` 테이블, `MarketNewsItem`·`MarketNewsItemType`, `MarketNewsItemRepository`가 이미 있다. 같은 뜻의 엔티티·enum을 하나 더 만들지 않는다.
- **머지된 `V13`을 수정하지 않는다** (ADR-0004). **이 이슈는 스키마를 바꾸지 않는 것이 기본이다** — 수집은 이미 있는 일곱 컬럼에 쓰기만 한다. 바꿔야 한다고 판단되면 §C-8·§데이터 모델을 먼저 확인하고, 그래도 필요하면 spec을 고친 뒤 **새 번호**로 낸다. 컬럼이 바뀌면 `FeedbackSchemaConstraintsTest`(일곱 테이블의 컬럼 → NULL 허용 맵 **전체 비교**)가 먼저 깨지므로 기대 맵도 같은 커밋에서 고친다 — 새 컬럼이 조용히 섞여 드는 것을 막으려는 의도된 설계다.
- **리포지토리에 지금 필요 없는 조회를 만들지 않는다.** `MarketNewsItemRepository`에는 조회 메서드가 하나도 없다. **아래 완료 조건을 검증하는 데 필요한 파인더(중복 판정)만** 더한다. 근거 매칭·요약·브리핑이 쓸 구간 질의는 #4·#5가 각자의 완료 조건과 함께 추가한다 — 지금 추측으로 만들면 시그니처가 어긋난 채 굳는다.
- **외부 API 키가 없어도 기동과 `./gradlew build`가 통과해야 한다** (ADR-0011, §실패 처리). **실제 외부 API를 호출하는 자동 테스트를 만들지 않는다** (PRD C-005 — 자동 테스트의 외부 네트워크 의존 금지).
- **`feedback`은 다른 도메인의 repository·store를 직접 주입하지 않는다**(§C-6). 종목 목록도 `market`의 서비스를 경유한다.
- **원장에 쓰지 않는다.** 수집 경로가 `market_news_items` 밖의 테이블에 INSERT·UPDATE 하지 않는다. `instruments`는 **읽기만** 한다. 8개 이슈 공통 조건인 "원장 불변"이 이 이슈에서 취하는 형태다.
- **새 설정 블록은 §C-7의 확정 방침을 따른다** — yml과 record `@DefaultValue` 양쪽에 값을 두고 드리프트를 잡는 테스트를 함께 둔다. `feedback.llm`(#147)이 선례다. 다만 **시크릿에는 `@DefaultValue`를 두지 않는다** — 이유가 §C-7에 있고 `kis.app-key`가 선례다(yml에서 빈 기본값 플레이스홀더).
- **`cron` 기반 `@Scheduled`에는 `zone`을 붙인다**(§C-1). 빠뜨리면 배포 JVM 기본 타임존이 UTC라 예외도 로그도 없이 엉뚱한 시각에 돈다.
- **공시는 주식만이다**(FEED-001). 코인에는 공시가 없다(§C-3).
- **근거 매칭·탐지·배치·조회 API·DTO·컨트롤러를 만들지 않는다.** 이 이슈는 기사를 모아 두기만 하고 어느 이벤트에 붙일지 판정하지 않는다. 목록은 아래 §이 이슈에서 하지 않는 것에 있다.
- **수집 진입점은 `feedback/service/`의 `NewsCollectionService`다.** §C-6에 이름이 없던 자리라 이번에 spec §C-6에 추가해 확정했다 — 수집기 4개는 §실패 처리상 "빈 목록을 반환"할 뿐이라 저장 주체가 따로 있어야 하고, 리포지토리에 쓰는 클래스는 서비스 계층이다(ADR-0002). 수집기는 그 서비스가 주입받는 바깥 어댑터라 `collector/`에 남는다.

## 작업 항목

- [x] **1. 수집 설정 블록과 환경변수 4종**

  수집이 읽을 설정을 먼저 세운다. 2~5번이 전부 이 블록을 참조하므로 순서상 맨 앞이다.
  - 크론 2종의 **프로퍼티 키 이름과 값은 §C-1**이 정본이다. **자격증명 3종의 키 경로는 §C-7**이 확정했다(`feedback.*` 밖 최상위, `kis.app-key`와 같은 형태), 환경변수 이름과 발급 출처는 §외부 API 호출 상세다.
  - 바인딩 형태는 §C-7 — record + `@DefaultValue` + yml 양쪽, 그리고 드리프트 테스트. `FeedbackLlmPropertiesTest`(record 기본값)와 `FeedbackLlmPropertiesIntegrationTest`(기동 컨텍스트의 `Environment` 키 경로) 쌍을 그대로 본뜬다. **시크릿은 예외**로 위 제약을 따른다.
  - **네이버 검색 API 키는 기존 OAuth 로그인 키와 별개 환경변수다**(§외부 API 호출 상세). `oauth.naver`가 쓰는 값을 재사용하면 검색과 로그인 중 하나가 조용히 깨진다.
  - `.env.example`에 신설 환경변수 4종을 추가한다. 주석은 기존 `KIS_APP_KEY` 항목처럼 **없을 때 무슨 일이 일어나는지**를 적는다.
  - `compose.deploy.yaml`의 `app` 서비스는 `env_file: .env`로 값을 통째로 넘기므로 4종이 그 경로로 따라간다. 완료 조건이 두 파일을 함께 지목하므로 **compose 쪽에서 이 4종이 어떻게 전달되는지 확인하고, 확인만으로 드러나지 않으면 드러나게 남긴다.** 뒤 이슈가 이 두 파일을 다시 건드리지 않도록 4종을 한 번에 넣는다.
  - 검증 — **완료 조건 "`.env.example`·`compose.deploy.yaml`에 신설 환경변수 4종"이 이 항목 소유다.** 드리프트 테스트로 yml과 record의 값이 갈리지 않는 것까지 본다.

  > **왜 독립 항목인가.** 설정과 환경변수 파일은 뒤 항목 전부의 전제이고, 충돌 주의 대상(`application.yml`의 `feedback.*`, `.env.example`, `compose.deploy.yaml`)이 이 항목에 모여 있다. 코드 커밋에 섞으면 뒤 이슈가 리베이스할 때 충돌 지점이 흩어진다.

- [x] **2. 종목별 검색 질의어 조립과 제목 필터 (순수 계산)**

  FEED-001의 두 규칙을 외부 의존 없는 순수 계산으로 만든다 — **코인 질의어 보정**과 **제목에 같은 시장의 다른 종목명이 있는 기사 제외**다.
  - 입력은 종목과 **같은 시장의 종목명 목록**, 그리고 기사 제목뿐이다. DB·시계·HTTP를 붙이지 않는다 — `PriceMoveDetector`를 순수 함수로 두는 이유와 같다(§C-6). 그래야 고정 픽스처로 단정할 수 있다.
  - **보정은 코인에만 붙는다**(FEED-001). 주식 질의어는 `instruments.name` 그대로다.
  - 제외 판정은 **같은 시장 안에서만** 한다. 시장을 섞으면 종목명이 겹치는 순간 정상 기사가 사라진다.
  - 검증 — 단위. **완료 조건 "코인 질의어에 보정이 붙고, 제목에 같은 시장의 다른 종목명이 있는 기사가 제외된다"가 이 항목 소유다.** FEED-001이 예로 든 접두 관계 종목쌍으로 **양방향**을 단정한다 — 다른 종목명이 든 제목은 빠지고, 자기 종목명만 든 제목은 남는다.

  > **근거 0건은 카드를 막지만 오탐 근거는 아무것도 막지 않는다**(FEED-001). 무관 기사가 제목·URL로 노출되고 LLM 입력에도 들어간다. 이 항목이 그 유일한 방어선이라 수집기보다 먼저, 단독으로 단정해 둔다.

- [x] **3. `NewsCollector` 인터페이스와 `FakeNewsCollector`·`NaverNewsCollector`**

  뉴스 수집기 3개를 만든다. 엔드포인트·질의 파라미터·헤더·`display` 제약은 §외부 API 호출 상세가 정본이고, 질의어와 제목 필터는 2번 것을 **쓴다**(다시 만들지 않는다).
  - 응답 매핑은 **제목·언론사·원문 URL·발행시각까지만**이다. 본문은 물론 **네이버가 주는 요약 스니펫도 담지 않는다**(§정책 전제 — 저작권). 담을 컬럼도 없다(§데이터 모델).
  - 제목에 HTML 엔티티가 섞여 온다(§C-8 `title` 비고). 저장 길이 제약도 같은 표에 있다.
  - **받은 기사를 발행일자로 거르지 않는다**(FEED-001). 최신순으로 받아 그대로 넘기고, 구간 필터는 조회·매칭 시점(#4·#5)에만 건다.
  - 키가 없을 때와 호출이 실패했을 때의 동작은 §실패 처리 그대로다 — Fake는 빈 목록, 호출 실패는 그 종목만 건너뛰고 `WARN`.
  - **Fake와 실제 구현의 선택은 프로필로 가른다** — 실제 구현에 `@Profile("prod")`, Fake에 `@Profile("!prod")`. `ResendEmailSender`/`FakeEmailSender`가 그대로 선례다. 로컬·테스트는 키 없이 Fake로 뜨므로 §실패 처리의 "키 없음 → Fake가 빈 목록. 기동·테스트 정상"을 만족하고, prod에 키가 아직 없는 구간은 같은 표의 "호출 실패 → 그 종목만 건너뜀"으로 흡수된다. **4번도 이 기준을 그대로 쓴다.**
  - 검증 — 단위. HTTP는 `MockRestServiceServer`로 고정한다(`KisHistoricalCandleClientImplTest` 선례). **실제 네이버 API를 부르는 테스트를 만들지 않는다.** ① 고정 응답이 제목·언론사·URL·발행시각으로 매핑되고 본문·스니펫이 어디에도 남지 않는다 ② 발행 시각이 제각각인 응답이 하나도 안 걸러진 채 그대로 나온다 ③ 호출이 실패해도 예외가 밖으로 나가지 않고 그 종목만 비어 돌아온다 ④ `FakeNewsCollector`가 빈 목록을 준다.

- [x] **4. `DisclosureCollector` 인터페이스와 `FakeDisclosureCollector`·`DartDisclosureCollector`, `corp_code` 매핑 리소스**

  공시 수집기 3개와 그것이 요구하는 매핑 리소스를 만든다. **OpenDART는 종목코드가 아니라 `corp_code`를 쓴다**(§외부 API 호출 상세) — 매핑을 미리 리소스로 만들어 두는 것이 `plan.md` §착수 전 확인 항목이다.
  - 매핑 리소스는 `src/main/resources`에 둔다. 형식은 `holidays-2026.txt` 선례처럼 단순 텍스트로 충분하다. **대상 종목 수는 §C-7**이다.
  - **매핑에 없는 종목은 건너뛴다. 오류가 아니다.**
  - 조회 구간 파라미터와 `published_at` 저장 규칙은 §외부 API 호출 상세, 날짜 축의 의미는 §C-3이다. `publisher` 고정값은 §C-8에 있다.
  - DART 호출 실패는 §실패 처리대로 — 공시 없이 뉴스만으로 진행한다. 3번이 정한 Fake/실제 선택 기준을 그대로 쓴다.
  - 검증 — 단위 + `MockRestServiceServer`. **실제 OpenDART를 부르는 테스트를 만들지 않는다.** ① 고정 응답이 §C-3·§C-8대로 매핑된다 ② 매핑에 없는 종목이 예외 없이 건너뛰어진다 ③ 호출 실패가 뉴스 경로를 막지 않는다 ④ 매핑 리소스가 §C-7의 주식 종목 전부를 덮는다.

- [x] **5. 수집 저장 경로와 상시 수집 스케줄 2종**

  수집기 결과를 `market_news_items`에 저장하고, 그것을 종일 돌리는 스케줄을 붙인다. **이 이슈의 완료 조건 4건이 여기서 확정된다.**
  - 저장은 `MarketNewsItem.create`를 쓴다. `created_at`은 발행 시각이 아니라 **수집 시각**이다(§데이터 모델) — #5의 요약 재생성 판정이 이 값을 본다.
  - **중복은 오류가 아니라 무시한다**(FEED-001). 중복을 판정할 파인더 **하나만** `MarketNewsItemRepository`에 더한다. 유니크 축은 §데이터 모델에 있다.
  - `@Scheduled` 2종을 건다. **크론 키와 값은 §C-1**이고 `zone`을 붙인다.
  - **장중으로 한정하지 않는다.** 뉴스 수집은 종일이다(§C-1·FEED-001). 그래야 §C-2의 `전장` 구간이 빈틈없이 채워진다 — 장중만 돌리면 그 구간 대부분이 **영영 수집되지 않는다.**
  - **`spring.task.scheduling.pool.size`를 이 이슈가 더하는 스케줄 수만큼 올린다.** 최종 합계와 계산 근거는 §C-1에 있다. `application.yml` 주석이 "기본 프로필의 `@Scheduled` 작업은 N개다"라는 불변식을 적어 두었으므로 **주석의 개수 계산도 같은 커밋에서 갱신한다** — 이슈 #125가 정확히 이 개수를 잘못 센 사고였다.
  - 수집 실패가 분봉 수집·재생세션 확정·주식 시장 개장을 막지 않는다(FEED-001·§실패 처리).
  - 검증 — 고정 `Clock` + Testcontainers 통합, 중복은 `@DataJpaTest`. **완료 조건 4건이 이 항목 소유다.**
    ① **기사 당일 수집** — Fake 수집기가 D의 기사를 주면 **D 시점에** 저장되고, D+1 배치 시점에 다시 긁지 않고 조회만 해도 그 기사가 있다. 재생 시점에 수집하는 경로가 없음을 함께 본다.
    ② **`전장` 구간이 빠짐없이 수집된다** — §완료 조건이 지목한 저녁·심야·아침 세 시각 발행 기사가 전부 저장·조회된다. **크론 표현식이 그 세 시각을 실제로 포함하는지 `CronExpression`으로 직접 단정한다** — 장중만 도는 크론이면 저장 테스트는 통과하는데 운영에서 구간이 통째로 빈다.
    ③ **발행일자로 거르지 않는다** — 어느 구간에도 걸리지 않는 발행 시각의 기사도 그대로 저장된다.
    ④ **원장 불변** — 수집 실행 전후로 주문·체결·계좌·잔액·보유·손익 테이블의 행이 변하지 않고, 저장 경로가 `market_news_items` 밖의 리포지토리에 쓰지 않는다.

- [x] **6. 외부 키 없이 `./gradlew build` 최종 확인과 코인 질의어 실측 기록**

  1~5번이 붙인 설정·빈·스케줄이 **키 4종이 하나도 없는 상태**에서도 성립하는지 마지막으로 확인한다.
  - 검증 — **완료 조건 "외부 API 키(네이버 검색·DART·OpenAI) 없이 `./gradlew build` 통과"가 이 항목 소유다.** 확인으로 끝내지 말고 **키가 없을 때 수집기 빈이 Fake로 잡히고 수집이 빈 결과로 끝난다**를 단정하는 테스트를 남긴다 (ADR-0011·§실패 처리). 1~5번도 각자 부분적으로 통과시키지만 **네 키가 모두 없는 조합을 한자리에서 고정하는 것은 여기**다.
  - **코인 질의어 보정 실측** — §튜닝의 "코인 질의어 보정" 행이 확인 방법과 조정 기준을 갖고 있다. 수집된 기사 목록에서 무관 기사 비율을 확인하고 **결과를 `run-log.md`에 남긴다.** 조정이 필요하면 코드가 아니라 FEED-001·§C-7을 먼저 고친다.
  - **실측은 이 이슈 착수 후에야 가능하다**(`plan.md` §착수 전 확인). 키가 없어 실측을 못 하면 **그 사실과 재확인 조건을 `run-log.md`에 남긴다** — 확인하지 않은 것을 확인한 것처럼 닫지 않는다.
