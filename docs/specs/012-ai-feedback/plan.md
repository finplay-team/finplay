## 왜 한 번에 8개를 만들지 않는가

spec은 구현 중에도 바뀐다. 이슈 8개가 먼저 존재하면 spec을 한 번 고칠 때마다 이슈 8개를 훑어야 하고, 반드시 한둘을 놓친다. 놓친 이슈를 보고 구현하면 낡은 규칙이 코드가 된다.

**계획은 이 문서 하나에 두고, 이슈는 착수할 때 만든다.** 아직 안 만든 이슈는 고칠 필요가 없다.

### 순서를 이렇게 잡은 이유

**1번이 LLM인 것이 핵심이다.** `spec.md` §외부 API 호출 상세가 Spring AI **2.0.0 이상**을 요구하는데(1.x는 Boot 3.x 전용), 이 조합은 **아직 검증되지 않았다.** 여기서 컨텍스트가 기동하지 않으면 나머지 7개의 전제가 통째로 바뀐다. 가장 싼 이슈에서 가장 비싼 위험을 먼저 터뜨린다.

**4번을 5·6번보다 앞에 둔다.** FEED-004가 개장 전 배치에서 FEED-002·003·008·009를 실행하므로, 5번은 4번이 만든 `FeedbackBatchService` 위에 얹힌다. 순서를 바꾸면 배치 골격을 두 번 만든다.

**5번이 Part C와 D를 함께 담는다.** 두 API가 09:00 하한을 공유하고, 완료 조건에 **"08:41에 두 API를 모두 호출"**하는 게이트 대칭 검증이 있다. 엔드포인트 단위로 자르면 그 조건의 소유자가 없어진다.

**7번을 6번에서 분리하되 붙여 둔다.** 둘 다 `PostSellFeedbackResponse`에 필드를 더하는 작업이라 동시에 하면 리베이스 충돌만 는다.

**8번이 마지막인 이유는 선행 작업이 딸려 있어서다.** 코인 감시는 `market`에 **가격 스냅샷 보관을 신설**해야 성립한다(`spec.md` §코인 가격 스냅샷). 없이 기존 조회로 대체하면 예외 없이 3.3시간 표본으로 계산돼 임계치 판정이 조용히 틀린다.

**병렬 여지** — `1 ∥ 2` → `3` → `4` → `{5, 6, 8}` → `7`. 다만 5·6·8이 `FeedbackBatchService`·`PostSellFeedbackResponse` 등 같은 파일을 건드리므로 **1인 진행이면 순차가 낫다**(`docs/parallel-agents.md`).

### 원장 불변은 전 이슈 공통이다

**"카드 생성·조회 전후로 주문·체결·계좌·잔액·보유·손익 원장이 변하지 않는다"는 한 이슈에 배정하지 않는다.** 이 spec의 어떤 코드도 원장을 건드리면 안 되므로 **8개 이슈 전부의 완료 조건에 넣는다.** 배치가 생기는 4번, 회원별 쓰기가 생기는 6번, 실시간 경로가 생기는 8번이 특히 위험하다.

같은 절의 나머지 3건은 성격이 달라 개별 배정한다 — 키 없이 build(1·3), `.env.example`(3), V13 `validate`(2).

## 이슈 본문 작성 규칙

`.github/ISSUE_TEMPLATE/feature.yml`의 5개 항목을 채운다.

| 항목 | 담을 것 |
|---|---|
| 기능 설명 | 무엇을 왜. **비즈니스 언어로.** 구현 방법은 spec에 있으니 적지 않는다 |
| 완료 조건 | 위 배정표의 해당 절을 옮긴다. 규칙은 `spec §X 참조`로 |
| 제외 범위 | 다음 이슈로 넘길 것을 번호와 함께 |
| 선행 / 충돌 주의 | `blocked by #NNN` + 같은 파일을 건드리는 이슈 |
| 관련 스펙 | `docs/specs/012-ai-feedback` |

**금지 사항 셋.**

- **값을 적지 마라.** 크론·임계값·범위·상태값은 전부 `spec.md` §확정값 참조다.
- **이슈 제목에 spec 번호(012)를 넣지 마라.** 브랜치명이 3자리를 spec 번호로 오독하는 문제가 있었다(`docs/git-conventions.md`).
- **완료 조건을 새로 만들지 마라.** spec에 없는 조건이 필요하면 spec을 먼저 고친다.

**예외 하나.** 이 문서와 이슈 본문이 **왜 그렇게 쪼갰는지 설명할 때는 클래스명·시각을 인용해도 된다** — "5번은 4번이 만든 `FeedbackBatchService` 위에 얹힌다" 같은 문장이다. 값을 **정의**하는 것과 근거를 **서술**하는 것은 다르다. 다만 그 값이 판단 기준이 되면(임계값·크론·범위) 반드시 §참조로 적는다.

## 착수 전 확인이 필요한 것

- **Spring AI 2.0.0 × Boot 4.1.0 호환** — 미검증. 1번 이슈에서 가장 먼저 확인한다.

- **OpenDART `corpCode.xml` 매핑** — 주식 종목의 `corp_code`를 미리 리소스로 만들어 둔다. 3번에서 필요하다.
