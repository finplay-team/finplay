## 개요

인증 사용자가 본인 소유의 매수 체결 1건에 투자일기 1건을 작성한다. 투자일기는 체결 이후의 기록이며 주문·체결·계좌·잔액·보유·FIFO lot·실현손익 원장을 변경하지 않는다. 이번 범위는 **작성 1개 엔드포인트**이며, 수정·목록·상세·매도 회고·AI 복기는 포함하지 않는다.

## 사용자 시나리오

- 사용자는 매수 체결 후 해당 체결에 투자일기 본문을 한 번 작성한다.
- 사용자는 매수가 아닌 체결이나 다른 사용자의 체결에는 투자일기를 작성할 수 없다.
- 사용자는 같은 매수 체결에 투자일기를 다시 작성할 수 없다.
- 사용자는 투자일기를 작성하지 않아도 매매·보유·커뮤니티 기능을 계속 사용할 수 있다.

## 요구사항

### JOUR-001 매수 투자일기 작성

- [ ] `POST /api/trades/{buyTradeId}/journal`로 투자일기를 작성한다.
- [ ] `buyTradeId`가 존재하는 매수 체결이며 인증 사용자 소유인지 검증한다.
- [ ] 매수 체결 1건당 투자일기 1건만 존재한다 (`UNIQUE(buy_trade_id)`).
- [ ] 이미 투자일기가 존재하면 409 `DUPLICATE_RESOURCE`로 거부한다.
- [ ] 본문은 공백이 아닌 텍스트여야 하며, 목표가·손절가·예상보유기간 같은 별도 필드는 이번 계약에 포함하지 않는다.
- [ ] 성공 시 투자일기 ID, 매수 체결 ID, 본문, 작성시각을 반환한다.

## 비즈니스 규칙

- 본인의 매수 체결에만 작성할 수 있다. 없는 체결은 404, 타인 체결은 403, 매수가 아닌 체결은 400으로 거부한다.
- 투자일기 저장과 소유권·중복 검증은 한 트랜잭션에서 처리한다.
- 투자일기 작성 성공·실패는 주문·체결·계좌·잔액·보유·FIFO lot·실현손익을 변경하지 않는다.
- 동시 중복 작성은 애플리케이션 검증과 `UNIQUE(buy_trade_id)` 제약으로 한 건만 성공시킨다.
- 투자일기는 원장(`trades`)을 **읽기만** 한다. 투자일기 쪽에서 체결·계좌·보유를 갱신하는 경로를 만들지 않는다.

## 범위 제외

이번 착수(JOUR-001)에서 하지 않는 것이다. 괄호 안은 다루는 PRD 요구사항이다.

- **매수 회고 수정** (JOUR-002) — `docs/prd.md`가 **Decision Gate 미해결**로 표시한 항목이다. `005-order-sell/spec.md`는 "첫 매도 배분이 발생한 매수 lot은 투자일기 수정이 잠긴다"고 규정하지만 **잠금 판정 시점·조건·오류 코드(`JOURNAL_LOCKED` 예정)가 팀 확정 전**이라, 수정을 지금 구현하면 잠금 없는 계약이 먼저 굳는다.
- **투자일기 상세 조회** (JOUR-005) — 역시 **Decision Gate 미해결**이다. 매수 회고와 매도 회고를 **같은 `journalId` 리소스로 조회할지, 식별자 체계를 분리할지**가 확정 전이다. 이 결정이 곧 리소스 URL과 응답 계약을 좌우하므로 확정 후 착수한다.
- **매도 회고 작성·수정** (JOUR-003·004)과 구 API `POST /api/trades/{id}/sell-journal`.
- **투자일기 목록 조회** (JOUR-006) — 커서 페이지네이션·`market` 축.
- 투자일기 삭제 (PRD에 요구사항 없음).
- 목표가·손절가·근거·예상보유기간 같은 구조화 필드.
- 첫 매도 전 수정 잠금과 `JOURNAL_LOCKED` 오류 코드.
- 투자일기 기반 AI 피드백·가격 알림·주간 회고 (spec 012 범위).
