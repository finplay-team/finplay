# Spec: 매수 체결별 투자일기 작성

> 단계: **2차 MVP (팀 회의 표현: 1차 고도화)**. 2026-07-28 Notion API 표 확인 결과 1차 MVP가 아님을 확인해 하향 조정.
>
> PRD 근거: PORT-004(§4에서는 제외되고 이 spec에만 요구사항 초안이 남아있음). 선행: `004-order-buy` (매수 체결).
> 2차 착수 시점에 plan.md·tasks.md를 작성하며, 요구사항도 그때 다시 확정한다 (지금은 착수하지 않는다).

## 개요

인증 사용자가 본인 소유의 매수 체결 1건에 투자일기 1건을 작성한다. 투자일기는 체결 이후의 기록이며 주문·체결·보유·손익 원장을 변경하지 않는다. 아래 요구사항은 2차 착수 전 초안이며, 작성 기능 자체를 포함해 수정·목록·상세·매도 회고·AI 복기 모두 2차(1차 고도화) 범위다.

## 사용자 시나리오

- 사용자는 매수 체결 후 해당 체결에 투자일기 본문을 한 번 작성한다.
- 사용자는 매도가 아닌 체결이나 다른 사용자의 체결에는 투자일기를 작성할 수 없다.
- 사용자는 같은 매수 체결에 투자일기를 다시 작성할 수 없다.
- 사용자는 투자일기를 작성하지 않아도 매매·보유·커뮤니티 기능을 계속 사용할 수 있다.

## 요구사항

### PORT-004 매수 투자일기 작성

- [ ] `POST /api/trades/{buyTradeId}/journal`로 투자일기를 작성한다.
- [ ] `buyTradeId`가 존재하는 매수 체결이며 인증 사용자 소유인지 검증한다.
- [ ] 매수 체결 1건당 투자일기 1건만 존재한다 (`UNIQUE(buy_trade_id)`).
- [ ] 이미 투자일기가 존재하면 409 `DUPLICATE_RESOURCE`로 거부한다.
- [ ] 본문은 공백이 아닌 텍스트여야 하며, 목표가·손절가·예상보유기간 같은 별도 필드는 MVP 계약에 포함하지 않는다.
- [ ] 성공 시 투자일기 ID, 매수 체결 ID, 본문, 작성시각을 반환한다.

## 비즈니스 규칙

- 본인의 매수 체결에만 작성할 수 있다. 없는 체결은 404, 타인 체결은 403, 매수가 아닌 체결은 400으로 거부한다.
- 투자일기 저장과 소유권·중복 검증은 한 트랜잭션에서 처리한다.
- 투자일기 작성 성공·실패는 주문·체결·계좌·잔액·보유·FIFO lot·실현손익을 변경하지 않는다.
- 동시 중복 작성은 애플리케이션 검증과 `UNIQUE(buy_trade_id)` 제약으로 한 건만 성공시킨다.

## 범위 제외

- 투자일기 수정·목록·단건 상세·삭제.
- 매도 체결 회고와 기존 구 API `POST /api/trades/{id}/sell-journal`.
- 목표가·손절가·근거·예상보유기간 같은 구조화 필드.
- 첫 매도 전 수정 잠금과 `JOURNAL_LOCKED`.
- 투자일기 기반 AI 피드백·가격 알림·주간 회고.

## 완료 조건

- [ ] 본인 매수 체결에 투자일기 작성 통합 테스트 통과.
- [ ] 같은 매수 체결의 순차·동시 중복 작성이 한 건만 성공하고 나머지는 409인 테스트 통과.
- [ ] 없는 체결·매도가 아닌 체결·타인 체결·공백 본문 거부 테스트 통과.
- [ ] 성공·실패 전후 주문·체결·계좌·잔액·보유·손익 원장이 변하지 않는 통합 테스트 통과.
- [ ] `./gradlew build` 통과.
