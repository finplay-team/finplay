# ADR-0010: 에이전트 세션 생명주기 — 역할별 재사용·재개·신규 전환

- 상태: 승인됨
- 날짜: 2026-07-25
- 관계: ADR-0005의 로컬 오케스트레이션과 ADR-0008의 4역할을 유지하고, 서브에이전트 세션의 재사용·재개 정책만 추가한다. ADR-0009의 Claude·Codex 공통 하네스 원칙에 이 정책을 얹는다.

## 맥락

/feature 실행에서 오케스트레이터는 작업 항목마다, 그리고 수정 루프마다 서브에이전트를 부른다. 스킬에 "재투입"이라고만 적혀 있어 실행자가 이를 매번 신규 서브에이전트 생성(콜드스타트)으로 해석했다. 실측(이슈 #2, 서브에이전트 10건·합계 약 39분)에서 수정 루프 3건이 방금 작성한 코드에 몇 줄을 고치려고 매번 spec·conventions·코드를 재로딩했고, 한 수정이 다른 테스트를 깨 왕복이 한 번 더 늘었다. 콜드스타트 재로딩과 불필요한 왕복이 시간과 토큰을 낭비한다.

동시에 리뷰·테스트·독립 검증을 줄여 시간을 버는 것은 금지한다(ADR-0005·0008의 품질 게이트 유지). 절감은 "같은 일을 다시 준비하는 비용"에서만 회수한다.

## 결정

- implementer는 한 /feature 실행 동안 세션 1개를 유지하고 작업 항목과 수정 루프에 재사용(재개)한다.
- production 버그·리뷰 차단은 코드를 작성한 동일 implementer 세션에 다시 전달한다. 신규 생성이 아니다.
- tester는 한 작업 항목과 그 수정 루프 동안 세션을 유지한다. 새 작업 항목으로 넘어갈 때 유지 여부는 오케스트레이터 재량이다.
- reviewer는 항상 신규 세션으로 실행한다. 구현자의 전제를 답습하지 않기 위한 독립성이 목적이다.
- planner는 무상태로 취급해 필요할 때마다 신규로 부른다.
- 세션을 재개할 때도 최소 packet 원칙을 지키고, 지난 턴 이후 메인 세션이 바꾼 파일 목록을 함께 전달한다.
- 다음 조건에서는 세션을 버리고 새로 만든다.
  - 무관한 도메인이나 다른 spec으로 전환
  - 컨텍스트 과다 누적
  - 같은 항목 3회 실패 고착
  - 설계 대전환
  - /feature 실행 종료. 다음 실행으로 세션을 끌고 가지 않는다.

## 도구별 실행 (메커니즘 분기)

- Claude Code는 완료된 서브에이전트를 SendMessage(agentId 또는 name)로 컨텍스트 유지한 채 재개한다(공식 지원). 실행 지침은 `.claude/skills/feature/SKILL.md`.
- Codex는 세션 재개를 지원하면 동일 세션을 재개하고, 지원하지 않으면 신규 spawn 패킷에 직전 구현 맥락과 변경 파일을 실어 동등한 연속성을 확보한다. 재개 지원 여부는 확인이 필요하다. 실행 지침은 `.agents/skills/feature/SKILL.md`.

## 범위 밖

- 테스트·리뷰·독립 검증 축소를 통한 시간 절감
- reviewer·planner의 세션 재사용
- /feature 실행 간 세션 유지

## 결과

- 콜드스타트 재로딩과 수정 루프 왕복이 줄어 시간과 토큰을 절감한다. 추정 13~25%이며 실측이 아니라 아래 지표로 검증한다.
- reviewer 독립성과 품질 게이트는 그대로 유지된다.
- 검증 지표는 /feature당 벽시계 시간, 서브에이전트 건수·시간 합계, 역할별 콜드스타트 대 재개 횟수, 왕복 횟수, 재작업률(한 수정이 다른 테스트를 깬 건수), 토큰 합계다. Testcontainers·full build 시간은 분리 측정해 순수 재로딩 절감분을 격리한다.
