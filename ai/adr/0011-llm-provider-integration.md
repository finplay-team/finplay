# ADR-0011: LLM 연동은 Spring AI 추상화 뒤에 두고 프로바이더를 설정으로 교체한다

- 상태: 승인됨
- 날짜: 2026-08-03
- 관계: C-004(AI 정책)를 구현 수준으로 구체화한다. ADR-0002의 레이어 구조를 따르며 새 도메인 패키지 `com.finplay.api.feedback`만 추가한다. `docs/specs/012-ai-feedback`의 선행 결정이다.

## 맥락

2차 AI 피드백(spec 012)이 외부 LLM을 호출한다. 이 저장소의 첫 LLM 의존성이며, 지금까지의 외부 연동(KIS·빗썸·Resend)과 성격이 다르다.

- **과금이 호출량에 비례한다.** KIS·빗썸은 무료 쿼터 안에서 쓰지만 LLM은 토큰당 과금이다.
- **출력이 비결정적이다.** 같은 입력에 같은 문장이 나오지 않는다. 테스트에서 문자열을 단정할 수 없다.
- **틀린 내용을 자신 있게 만들어낸다.** 근거 없이 그럴듯한 인과를 지어내는 것이 기본 동작에 가깝다.
- **프레임워크가 Boot 버전과 강결합된다.** Spring AI 1.x는 Boot 3.x 전용이라 이 프로젝트(Boot 4.1.0)에서 컨텍스트가 기동하지 않는다. 2.0.0부터 Boot 4.0/4.1을 지원한다.

프로바이더 선택도 유동적이다. 팀이 이미 보유한 크레딧이 무엇인지에 따라 Anthropic과 OpenAI 사이에서 바뀔 수 있고, 3차의 RAG 챗봇에서 같은 결정을 다시 하게 된다.

## 결정

**LLM 호출을 `NarrativeGenerator` 인터페이스 하나로 감싸고, 그 뒤에 Spring AI를 둔다. 프로바이더는 설정으로 교체한다.**

- 서비스 로직은 `NarrativeGenerator`만 알고 어떤 모델·프로바이더인지 모른다.
- 프로바이더 교체는 `build.gradle`의 starter 의존성과 `feedback.llm.*` 설정값 변경으로 끝난다. 서비스 코드는 바뀌지 않는다.
- Spring AI는 **2.0.0 이상**을 쓴다. 1.x는 Boot 3.x 전용이다.
- 모델·타임아웃·최대 토큰은 전부 프로퍼티로 뺀다. 코드에 상수로 박지 않는다.

**LLM 실패를 정상 경로로 취급한다.**

- 키가 없거나, 호출이 실패하거나, 타임아웃이면 **서버가 수치로 조립한 템플릿 문장으로 대체**한다. 예외를 위로 던지지 않는다.
- `narrative_source`에 `LLM`·`TEMPLATE`·`NONE`을 기록해 사후에 비율을 볼 수 있게 한다. **`NONE`은 뉴스 요약·브리핑 전용**이다 — 여러 기사를 종합하는 요약은 수치 조립으로 대체할 수 없어 템플릿이 없고, 후검증에 걸리면 서술 자체가 비기 때문이다.
- **어떤 LLM 실패도 주식 개장·주문·체결을 막지 않는다.** 이 기능은 부가 정보이고 원장이 본체다.

**출력을 신뢰하지 않고 후검증한다.**

- 서버가 정규식으로 인과 단정·투자 권유·가격 예측·조언·판단 표현을 거른다. **카드와 매도 회고는 걸리면 곧바로 템플릿으로 대체**한다.
- **요약·브리핑은 템플릿이 없어 처리가 다르다** — 걸린 표현을 프롬프트에 되돌려 주고 1회만 재생성하며, 그래도 걸리면 `summary=null`·`narrative_source=NONE`으로 둔다. 기사 제목에 `전망` 같은 금지어가 흔해 재생성 경로가 없으면 요약 기능이 통째로 사라진다.
- 프롬프트 지시만으로는 부족하다는 전제에서 출발한다.
- **근거가 없으면 호출하지 않는다.** 관련 기사가 0건인 구간은 카드를 만들지 않는다. "무언가 써 보라"고 시키면 지어낸다.

**호출량을 사용자 수와 분리한다.**

- 생성 결과는 회원별이 아니라 `(종목, 원본 거래일, 구간)` 단위로 만들어 전 회원이 공유한다. 재생 방식이라 모든 회원이 같은 분봉을 보므로 성립한다.
- 결과적으로 하루 호출량이 **사용자 수와 무관하게** 고정된다. 회원별 생성은 매도 회고뿐이고 그것도 체결 1건당 1회이며 저장 후 재사용한다.
- **호출량 추정 (2026-08-04 갱신, 이슈 #136)** — 초기 "약 120건"은 코인 요약·브리핑의 온디맨드 생성을 빠뜨린 값이었다.

  종목 수는 spec §C-7(`instruments.stock-count` 16 / `crypto-count` 12) 기준이며, 그 값을 바꾸면 이 표도 함께 갱신한다.

  | 경로 | 하루 호출 |
  |---|---|
  | 주식 변동 카드 (16종목 × 최대 3건) | ~48 |
  | 주식 뉴스 요약 (16종목 × PRE_MARKET·FULL) | 32 |
  | 주식 개장 전 브리핑 | 1 |
  | 코인 변동 카드 (12종목 × 상한 6건, 근거 부족으로 실제는 훨씬 적다) | ≤72 |
  | 코인 뉴스 요약 (12종목 × 매시 배치 24회) | ≤288 |
  | 코인 브리핑 (매시 배치) | ≤24 |
  | 요약·브리핑 후검증 재생성 1회 | 위의 일부에 가산 |
  | **합계 (상한)** | **~465** |

  코인 쪽이 상한을 좌우한다. **전부 스케줄 배치라 사용자 수·조회 수와 무관하게 상한이 고정된다** — 조회 시 생성을 없앤 이유가 이것이다(2026-08-04, 이슈 #136). 코인 요약·브리핑은 직전 생성 이후 새 기사가 없으면 호출을 건너뛰므로 실제값은 상한보다 훨씬 낮다. 모델 기본값(spec §C-7)의 실호출 실측이 요약 1건당 완료 토큰 70 안팎·추론 토큰 0이라 호출 1건이 작다 — 다만 **월 비용은 추정하지 않고 첫 달 청구서로 확인한다.**

**수치·판정은 LLM에 맡기지 않는다** (C-004).

- 변동률·구간 판정·수익률·반사실 계산은 전부 서버가 한다.
- LLM 입력에는 이미 확정된 값만 넣고, 출력에서 수치를 다시 읽지 않는다.

**테스트는 Fake로 한다.**

- `NarrativeGenerator`의 Fake 구현으로 단위·통합 테스트를 돌린다. 실제 API를 호출하지 않는다.
- **API 키 없이 `./gradlew build`가 통과해야 한다** — KIS·Resend 키와 같은 방침.
- 문자열 일치를 단정하지 않는다. 후검증 통과 여부, `narrative_source` 값, 템플릿 폴백 동작을 단정한다.

## 결과

**좋은 점**

- 프로바이더 교체 비용이 설정 수준으로 떨어진다. 크레딧 상황이 바뀌어도 코드를 안 고친다.
- LLM이 죽어도 서비스가 죽지 않는다. 문장 품질만 내려간다.
- 키 발급을 기다리지 않고 구현·테스트를 끝낼 수 있다.
- 3차 RAG 챗봇이 같은 추상화를 재사용한다.

**받아들이는 대가**

- 추상화 계층이 하나 늘어난다. C-002(최소 구현)와 긴장 관계지만, 프로바이더가 실제로 바뀔 수 있고 3차에서 재사용된다는 근거가 있어 "한 번만 쓰는 추상화"에 해당하지 않는다고 판단했다.
- Spring AI가 Boot 버전에 강결합돼 있어 **Boot을 올릴 때 Spring AI도 같이 올려야 한다.** 버전 조합을 잘못 잡으면 기동 자체가 실패한다.
- 프로바이더별 응답 특성 차이(문장 길이·말투)는 추상화가 흡수하지 못한다. 교체하면 프롬프트와 후검증 비율을 다시 봐야 한다.
- 정규식 후검증은 완전하지 않다. 목록에 없는 표현은 통과한다. `TEMPLATE` 비율을 지표로 삼아 프롬프트를 조정하는 절차로 보완한다.

## 대안과 기각 사유

**공식 SDK를 직접 쓴다** (`com.anthropic:anthropic-java` 등)

의존성이 하나로 줄고 Boot 버전 결합도 없다. 그러나 프로바이더를 바꾸면 호출 코드를 다시 써야 한다. 크레딧 상황에 따라 실제로 교체가 검토되고 있어 기각했다.

**`RestClient`로 REST를 직접 호출한다**

의존성이 0개다. 그러나 스트리밍·재시도·에러 매핑을 직접 구현하게 되고, 3차 RAG에서 같은 작업을 반복한다.

**LLM을 아예 쓰지 않고 템플릿 문장만 쓴다**

비용·장애·환각이 전부 사라진다. 실제로 이 경로는 **폴백으로 이미 구현한다.** 다만 여러 기사를 종합하는 요약과 매매 흐름 서술은 수치 조립으로 대체할 수 없어 기본 경로로 삼지 않았다.
