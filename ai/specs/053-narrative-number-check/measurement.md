## ①② 결과 — 대조군 2026-08-22(구현 착수 전) · 새 검증기 2026-08-23(구현 후)

**기존 검증기 열은 FEED-014~017 구현 전에 잰 값이다.** 구현 후에는 이 숫자를 다시 만들 수 없어 먼저 남겼다.
새 검증기 열은 같은 주입 집합을 `NarrativeNumberValidator`로 다시 잰 값이며, **두 열이 같은 실행에서
같은 하네스로 나온다** — 표를 손으로 옮겨 적지 않는다.

| | 기존 검증기 | 새 검증기 | 성격 |
|---|---|---|---|
| ① 숫자 환각 적발 | **0 / 12** | **12 / 12** | 운영에서 실제로 나올 수 있는 오류 |
| ② 가정법 문장 차단 | **6 / 6** | **6 / 6** (변화 없음) | **합성 입력 — 운영 발생 이력 없음** |

**①의 0 → 12가 이 spec의 성과다.** 열두 건의 적발 사유는 아래와 같고, 전부 서술에서 뽑은 원문 토큰이다.

```
[-21.7]    ← 수익률은 -21.7%였습니다.
[-152,070] ← 실현손익은 -152,070원이었습니다.
[1,050]    ← 매수는 첫 근거 기사보다 1,050분 앞섰습니다.
[+15,207]  ← 실현손익은 +15,207원이었습니다.
[+2.17]    ← 수익률은 +2.17%였습니다.
[+1.82]    ← 보유 구간에 걸친 변동은 +1.82%였습니다.
[15,000]   ← 실현손익은 약 15,000원이었습니다.
[110]      ← 매수는 첫 근거 기사보다 110분 앞섰습니다.
[68,000]   ← 매도가는 68,000원이었습니다.
[69,500]   ← 20일 이동평균선은 69,500원이었습니다.
[2.4]      ← 거래량은 직전 5거래일 평균의 2.4배였습니다.
[5.12]     ← 장중 고점 대비 5.12% 낮은 가격에 매도했습니다.
```

부호 3건(`+15,207`·`+2.17`·`+1.82`)이 잡힌 것은 **서술이 부호 기호를 붙였기 때문이다.** 기호 없이
"15,207원 이익"이라고만 썼다면 통과했다 — 그것은 숫자 환각이 아니라 방향을 뒤집은 서술 오류이며,
이 spec은 그 축을 열지 않았다(§결정 1의 한계). **발표에서 성과와 함께 밝힌다.**

**②를 성과로 읽지 않는다.** 6/6 차단은 고쳐야 할 결함이 아니라 `012` §왜 반사실은 AI 문장에 넣지 않는가의
제품 판단이 코드에서 지켜지고 있다는 뜻이다. 이 spec은 그 숫자를 바꾸지 않는다(2026-08-23 범위 축소).

주입 케이스는 자릿수 3 · 부호 3 · 반올림 3 · 출처 없음 3으로 열두 건이고, 반사실은 가정법 어미 다섯
(`았다면`·`었다면`·`였다면`·`했다면`·`렸다면`)을 모두 덮는 여섯 건이다.

**두 집합의 성격이 다르다.**

- **①의 12건은 운영에서 나올 수 있다.** LLM이 자릿수를 옮기거나 없던 수치를 지어내는 것을 지금은 시스템
  프롬프트 지시로만 막고 있고, 후검증에는 대응 규칙이 하나도 없다. 다만 **실제 발생률은 재지 않았다** —
  운영 서술 표본을 모아 세지 않았으므로 "발생하면 못 잡는다"까지만 말할 수 있다.
- **②의 6건은 운영에서 발생한 적이 없다.** 반사실은 프롬프트에 들어간 적이 없어 LLM이 이 문장을 쓸 재료를
  받은 적이 없다. **순수한 합성 입력**이며, 분리된 후속 이슈(반사실 해금)의 착수 전 기준선으로만 쓴다.

②의 차단 사유는 구현 전에 전부 가정법 어미 하나뿐이었고, 구현 후에는 여기에 숫자 축의 적발이 하나씩
더 붙었다. 아래는 운영 경로 그대로 두 축을 합친 결과다(표현이 앞, 숫자가 뒤).

```
[했다면, -1.17] ← 마감까지 보유했다면 수익률은 -1.17%였습니다.
[았다면, +1.11] ← 보유 중 최고가에 팔았다면 +1.11%였습니다.
[었다면, -1.17] ← 매도하지 않고 그대로 두었다면 -1.17%였습니다.
[였다면, -1.17] ← 같은 수량을 69,200원에 매도하였다면 -1.17%였습니다.
[렸다면, -1.17] ← 매도를 미루고 마감까지 기다렸다면 -1.17%였습니다.
[했다면, +1.11] ← 11:05의 70,800원에 매도했다면 +1.11%였습니다.
```

표현 축의 사유가 여전히 가정법 어미 하나뿐이라는 것은 **차단이 의도대로 좁게 작동하고 있다**는 뜻이다 —
다른 24개 표현에는 걸리지 않았다. 숫자 축이 함께 잡은 것은 반사실 수익률(`-1.17`·`+1.11`)이며, 같은 문장의
가격(`69,200`·`70,800`)과 시각(`11:05`)은 프롬프트에 있어 걸리지 않았다. **차단 건수는 6/6 그대로다** —
사유가 하나 늘었을 뿐 판정은 달라지지 않았다.

## 대조군을 어떻게 얼렸나

테스트가 `NarrativeValidator`를 대조군으로 직접 쓰지 않고 **금지 표현 37개를 테스트 안에 복사해 두었다.**
FEED-014가 그 클래스에 숫자 대조를 더하면 운영 검증기는 ①의 12건을 적발하기 시작하고, **그 순간 "0/12"를
다시 만들 수 없기** 때문이다.

②는 사정이 다르다. 범위 축소로 표현 목록을 건드리지 않게 됐으므로 **운영 검증기도 구현 후에 계속 6/6을
낸다.** 그래도 얼린 목록을 그대로 쓰는 것은 ①②를 같은 기준으로 재기 위해서다.

얼린 목록이 오늘의 운영 검증기와 같은 판정을 낸다는 것은 `todaysValidatorReproducesTheFrozenBaseline`이
같은 실행에서 확인했다.

**그 테스트에 적어 둔 예고는 빗나갔다 — 구현 후에도 ① 쪽 단정이 깨지지 않았다.** 예고는 숫자 대조가
`NarrativeValidator` 안으로 들어간다는 전제 위에 있었는데, 실제 구현은 **별도 클래스
`NarrativeNumberValidator`로 뺐다**(plan.md §결정 A). `validateCardOrPostSell`의 판정이 무변경이라
**운영 클래스에서도 ①의 0/12가 그대로 재현된다.**

그래서 얼려 둔 것이 헛수고였느냐 하면 그렇지 않다. **대조군을 구현과 무관하게 고정해 두는 것이 이 하네스의
값이고**, 설계가 다른 쪽으로 갔더라면(같은 클래스에 축을 더했더라면) 0/12는 실제로 사라졌을 것이다. 얼린
목록 `LEGACY_RULES`는 그대로 둔다. 그리고 이 테스트는 이제 역할이 하나 바뀌었다 — **표현 축이 한 글자도
움직이지 않았다는 FEED-016의 증거**다.

## 12/12을 어디까지 믿을 수 있나 (한계)

**이 표를 발표에서 인용할 때 함께 말해야 하는 것이다.**

허용 집합이 프롬프트 문자열의 모든 수라(§결정 2) **콜론이 토큰 경계가 되어 시각이 갈려 들어온다** —
`11:15`는 `11`과 `15`, `14:40`은 `14`와 `40`이다. 매도 회고 프롬프트에는 시각이 여러 개 있으므로
**결과적으로 0~59 범위의 정수 대부분이 허용 집합에 들어온다.**

골든 마스터 프롬프트로 실제로 확인한 예다.

```
매수는 첫 근거 기사보다 15분 앞섰습니다.   ← 실제 105분. `15`가 `11:15`에서 와 통과한다.
40주를 매수했습니다.                      ← 실제 10주. `40`이 `14:40`에서 와 통과한다.
```

**즉 `분`과 수량처럼 값이 작은 정수 필드는 이 축으로 사실상 대조되지 않는다.** ①의 12/12는 주입한 오답이
전부 60을 넘기거나(`110`·`1,050`·`152,070`) 소수를 포함해(`2.4`·`5.12`·`-21.7`) 얻은 결과다. **"모든 숫자
환각을 잡는다"가 아니라 "자릿수·부호를 바꾸거나 없던 수를 지어낸 열두 갈래를 잡는다"가 정확한 진술이다.**

콜론을 붙여 `09:30`을 한 덩어리로 두면 이 구멍은 막히지만 **"09시 30분에 매수했습니다"라는 정상 서술이
전부 위반**이 되어 매도 회고가 통째로 템플릿으로 떨어진다. 그래서 구멍 쪽을 택했다 — 잡히는 것이 줄어드는
대가는 폴백 한 번이지만, 반대 방향의 대가는 기능이 사라지는 것이다.

**허용 집합은 위치 정보가 없는 값 주머니다.** 어떤 수가 어느 필드에서 왔는지 기억하지 않고 "프롬프트에
그 수가 있었나"만 본다. 그래서 **서로 다른 필드의 값을 맞바꿔 써도 잡히지 않는다** (PR #538 리뷰 지적).

```
매수는 68,500원에, 매도는 70,000원에 이뤄졌습니다.   ← 실제는 정반대. 두 수 모두 프롬프트에 있어 통과한다.
```

이 예는 **모든 수가 출처를 갖는데도 문장 전체가 거짓**인 경우다. 손익의 방향이 뒤집히므로 앞의 세 한계보다
결과가 크다. 최고가율↔최저가율(`3.25%`↔`0.59%`), 매수 시각↔매도 시각도 같은 형태로 새어 나간다.

막으려면 대조가 **값 주머니가 아니라 (필드, 값) 쌍**이 되어야 하는데, 그러려면 서술의 어느 수가 어느 필드를
가리키는지 알아야 한다 — 그것은 "매수는·매도는" 같은 **표현을 읽는 일**이라 053이 벗어나려던 자리로
되돌아간다. 이 spec은 그 축을 열지 않는다.

같은 성격의 한계가 하나 더 있다. **부호를 말로만 뒤집은 문장**(`-2.17%`를 받고 "2.17% 이익"이라 쓰는 경우)도
이 축으로 잡지 못한다(§결정 1).

**네 한계를 한 줄로 요약하면 이렇다.** 이 축은 **"이 수가 어디서 왔나"를 보장하고 "이 수를 맞게 썼나"는
보장하지 않는다.**

## 아직 재지 않은 것

- **③ 템플릿 폴백률 변화** — **여전히 미측정.** 실호출이 필요하다. `012` §후검증이 정한 `TEMPLATE` 30% 선이
  판정 기준이고, 넘으면 대조 규칙이 아니라 프롬프트를 손본다. 폴백이 늘어난 건은 진짜 환각인지 정상 문장이
  표기 차이로 걸린 것인지 **갈라 기록한다.**
- **①의 실제 발생률** — 운영 서술 표본을 모아 세는 것은 이번 범위가 아니다. ①의 12/12는 "발생하면 잡는다"이지
  "자주 발생한다"가 아니다. 재지 않았다는 사실을 발표에서도 밝힌다.
- **방향을 말로만 뒤집은 서술** — 측정하지 않았다. `-2.17%`를 받고 "2.17% 이익"이라 쓰는 경우인데, 부호 기호가
  없어 숫자 축이 통과시킨다(§결정 1의 한계). 이 spec은 그 축을 열지 않았다.

①②는 **끝났다**(위 표). 남은 것은 위 세 가지이며 셋 다 이번 범위 밖이다.
