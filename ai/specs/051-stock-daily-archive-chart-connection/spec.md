# Spec: 주식 일봉 3년 아카이브를 캔들 조회 API에 연결

- 대응 이슈: [#506](https://github.com/finplay-team/finplay-backend/issues/506) 결정 1·2 및 완료 조건 6·7
- 요구사항 ID: MKT-011 (수집·저장은 `050-stock-daily-archive`에서 완료, 이 spec은 조회 연결)
- 차수: 2차 고도화(3차 MVP)

## 개요

`050-stock-daily-archive`(PR #508)로 `stock_daily_candles`에 3년치 일봉을 수집·저장했지만, 캔들 조회 API(`GET /api/instruments/{id}/candles`, `interval=1d`\|`1w`\|`1M`)는 여전히 `stock_candles`(1분봉, 배포 후 며칠치만 존재)만 읽어 차트가 며칠치로만 보이는 문제가 배포 직후 실사용에서 확인됐다. 이 spec은 조회 경로를 아카이브에 연결한다.

**배경**: PR #508 머지 직후 실제 배포 환경에서 주식 일봉 차트가 6일치만 보이는 문제가 보고됐다(2026-08-21). 원인은 정확히 이 연결의 부재였다 — 이슈 #506이 처음부터 "착수 전 결정 필요"로 남겨둔 항목이 실사용에서 그대로 드러난 것이다.

## 착수 전 결정 필요 — #506이 남긴 두 결정을 여기서 확정한다

**결정 1(시간축, #506 결정 1)**: 아카이브는 **과거(재생거래일 이전) 구간에만** 쓴다. 재생 중인 당일(sourceTradingDate)은 계속 1분봉 컷오프 경로만 쓴다 — 기존 `buildAggregatedCandles`의 `pastEnd = min(rangeEnd, sourceTradingDate-1)` 클램프를 그대로 재사용해 아카이브 쿼리 자체가 `sourceTradingDate` 이후를 절대 조회하지 않는다. 새 게이트를 만들지 않고 기존 클램프에 편승한다 — 과거 구간은 이미 확정된 기록이라 재생 모델의 "미래 노출" 위험이 원천적으로 없다.

**결정 2(이중 소스, #506 결정 2)**: **거래일 하나는 항상 하나의 소스에서만 나온다.** 과거 구간에서 아카이브에 그 거래일이 있으면 아카이브(KIS 확정 종가, 수정주가)를 쓰고, 아카이브가 아직 그 날짜를 못 채운 경우(최초 적재 직후·배치 지연)에만 1분봉 집계로 보충한다. 같은 거래일이 두 소스에서 동시에 나오거나 병합되지 않는다 — 값이 섞이지 않는다.

## 요구사항

- [ ] **CHART-CONN-001** `interval=1d`\|`1w`\|`1M` 조회의 과거 구간(재생거래일 이전)은 `stock_daily_candles`를 우선 소스로 쓴다.
- [ ] **CHART-CONN-002** 아카이브에 없는 과거 거래일은 `stock_candles` 1분봉 집계로 보충한다(회귀 없음 — 기존 응답 계약·필드·200개 캡·커서 페이지네이션 전부 그대로).
- [ ] **CHART-CONN-003** 재생 중인 당일(sourceTradingDate)은 아카이브를 절대 참조하지 않는다 — 항상 기존 1분봉 컷오프 경로.
- [ ] **CHART-CONN-004** `interval=1m` 조회는 이 spec의 대상이 아니다 — 무변경(이슈 #495가 여전히 별도 결정 대상).
- [ ] **CHART-CONN-005** 조회 범위를 좁히는 최적화(`narrowRangeStart`)가 아카이브 전용 구간을 잘못 잘라내지 않는다 — 1분봉·아카이브 두 소스의 거래일을 합쳐서 narrowing을 계산한다.

## 비즈니스 규칙

- 아카이브 값이 1분봉 집계 값과 다를 수 있다(정규장 분봉 합산 vs KIS 확정 종가·수정주가) — 이건 데이터 소스가 다르기 때문이며 서버가 보정하지 않는다(#506 결정 2에서 이미 인지).
- 아카이브 조회는 확정된 과거 기록만 다루므로 재생 노출 게이트(reveal bound)의 대상이 아니다.

## 범위 제외

- `interval=1m`(이슈 #495, 미착수).
- 코인(계속 빗썸 위임, MKT-009 무변경).
- 아카이브의 페이지 상한 gap-fill(이슈 #511, 별개 후속).

## 완료 조건

- [ ] 과거 거래일 중 아카이브에만 있는 날짜·1분봉에만 있는 날짜가 섞여도 응답에 봉이 하나도 빠지지 않고, 날짜당 정확히 하나의 소스 값만 나온다 — 통합 테스트로 검증(`CandleQueryServiceIntegrationTest`).
- [ ] 재생 중인 당일에 아카이브가 같은 날짜의 값을 갖고 있어도 그 값이 응답에 노출되지 않는다(공개 상한 회귀 테스트).
- [ ] 기존 회귀 테스트(`aggregatedIntervalsSpanMultipleTradingDaysWhileOneMinuteRegressionHolds` 등) 전부 그대로 통과.
- [ ] `./gradlew build` 통과.
