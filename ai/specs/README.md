# specs — 기능 명세 (spec-kit 스타일)

기능 하나당 폴더 하나. 번호는 3자리 순번.

## spec은 계획 시점의 기록이다 (2026-08-20 신설)

`spec.md`·`plan.md`·`tasks.md`는 착수 시점의 계획을 담은 기록이며, 그 기능이 출시된 뒤 다른 이슈로 변경·축소·제거돼도 **소급해서 갱신하지 않는다.** 지금 무엇이 실제로 동작하는지는 `ai/prd.md` §3 "구현 현황"과 `docs/api/`(도메인별 계약 파일)가 정본이다 — ADR을 수정 대신 새 번호로 대체(superseded)하는 것과 같은 이유다(CLAUDE.md 규칙 2).

## 번호 규칙 — 유일성과 충돌 회피 (2026-08-10 신설)

- **번호는 저장소 전체에서 유일하다.** PRD·`api-routes.md`·`docs/api/`·다른 spec은 `016`·`026`처럼 **번호만으로** spec을 지목하므로(예: `ai/api-routes.md`의 근거 칸), 같은 번호가 둘이면 그 참조가 어느 문서를 가리키는지 판별할 수 없게 된다.
- **새 spec을 만들기 직전에 `git ls-tree origin/dev ai/specs/`로 다음 빈 번호를 확인한다.** 로컬 `ls`만 보면 병렬 브랜치가 선점한 번호를 놓친다 — Flyway 마이그레이션 번호와 같은 종류의 선점 충돌이며 `ai/agent-mistakes.md`에 동형 사례가 있다(ADR-0004).
- **origin/dev에 아직 없어도 진행 중인 PR이 그 번호를 쓰고 있을 수 있다.** 같은 날 병렬 작업이 있으면 `gh pr list`로도 확인한다 — 2026-08-10에 `026`이 두 브랜치에서 동시에 생성된 실제 사례가 있다.
- **충돌을 발견하면 나중에 생성된 폴더를 다음 빈 번호로 옮기고**, 그 폴더를 가리키던 참조(문서·테스트 주석)를 같은 커밋에서 전부 갱신한다. 이미 머지된 번호를 재사용하지 않는다.
- **결번은 메우지 않는다.** `017`·`044`는 비어 있고 그대로 둔다 — 번호는 시간 순서가 아니라 식별자다. (`044`는 커뮤니티 배지 spec이 팀 결정으로 완전히 철회되며 폴더째 삭제됐다 — 이슈 #481, PR #484)

```
specs/
└── 001-member-auth/
    ├── spec.md      # 무엇을, 왜 (요구사항, 시나리오, 완료 조건)
    ├── plan.md      # 어떻게 (기술 설계, API 명세, 스키마)
    ├── tasks.md     # 작업 분해 체크리스트
    └── run-log.md   # 실행 로그 (implementer·reviewer가 자동 기록, /feature 진행 중에만 생김)
```

## 흐름

1. 기능 논의 후 `spec.md` 작성 — 구현 세부사항 없이 요구사항과 완료 조건만.
2. spec 합의 후 `plan.md` — 엔드포인트, 테이블 설계, 관련 ADR 링크.
3. `tasks.md`로 분해 후 이슈 생성 → 구현.
   - 항목 굵기: **커밋 1개 = 응집된 기능 조각** (엔티티+repository+마이그레이션 한 덩어리 등). 너무 잘게 쪼개면 /feature 루프의 에이전트 투입 오버헤드가 작업 시간을 지배한다. spec 하나당 3~7개 권장.

AI에게 시킬 때는 "specs/001-member-auth 진행해줘"처럼 폴더 단위로 지시한다.
템플릿은 `_template/`을 복사해서 시작한다.

## run-log.md — 실행 로그

/feature 루프에서 **implementer·reviewer만** 작업 종료 시 자동으로 남긴다 (tester·planner는 기록하지 않음 — 경량 시작 원칙, 필요해지면 확대). 사람이 직접 쓰는 파일이 아니다.

```md
# Run Log: 001-member-auth

## AI 로그 (에이전트 참조용)
| 시각 | 에이전트 | 실행 명령 | 근거 |
|---|---|---|---|
| 22:05 | implementer | `.\gradlew.bat compileJava` | plan.md 구성요소 설계, ADR-0002 |
| 22:20 | reviewer(리뷰) | `git diff dev...HEAD` | conventions.md, ADR-0003 |

## 모니터링 (사람용 요약)
- 22:05 — Redis compose·Testcontainers 싱글턴 추가, 컴파일 통과.
- 22:20 — 리뷰 완료, 차단 0건, 머지 가능.
```

- 각 행·줄은 1줄. 장문 금지 (부담이 되면 경량화 원칙 위반).
- 다음 에이전트가 같은 spec에 재투입될 때 직전 판단 근거를 빠르게 참고하는 용도. `ai/context-router.md`의 "기능 구현" 행에서 참조하지 않는다 — 필요할 때만 훑어보는 보조 자료.
