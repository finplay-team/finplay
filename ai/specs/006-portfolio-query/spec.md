# Spec: 조회 (계좌 요약 · 합산 포트폴리오 · 보유자산 · 주문 목록 · 거래내역)

> PRD 근거: ACCT-002, ACCT-003, PORT-001, PORT-002, PORT-003. 선행: `004-order-buy`, `005-order-sell`.
> plan.md·tasks.md는 착수 직전 작성한다.
>
> **후속 이력 — 주문 목록 페이지네이션 (1차 고도화, 이슈 #182)**: 이 spec은 1차 MVP 계약으로 PORT-003(주문 목록)에 `market` 파라미터도 페이지네이션도 없다고 못박았다. 그 제약은 PRD **PORT-003**(2026-08-04 확정, 이슈 #177 — [PR #178](https://github.com/finplay-team/finplay/pull/178))에 따라 2차 MVP(1차 고도화)에서 `market` 필수 + 커서 기반 페이지네이션(`cursor`·`limit`)으로 확장되었으며, 확장 계약은 **`docs/specs/018-order-list-pagination/`**에 있다. 아래 PORT-003 절의 "MVP에서는 페이지네이션 없이 전체 주문을 반환한다" 서술은 **당시 계약을 기록한 이력**이므로 지우지 않고 그대로 둔다 — 현재 유효한 주문 목록 계약은 018과 `docs/api-contracts.md`다.

## 개요

시장별 계좌 요약과 주식·코인 합산 포트폴리오, 보유자산 목록, 주문 목록, 거래내역을 조회 API로 제공한다. 평가값은 저장하지 않고 조회 시점의 최신 시세로 계산한다. QueryDSL 기반 목록 조회를 포함한다.

## 사용자 시나리오

- 사용자는 시장별 계좌의 현금잔고·보유평가액·총평가액·실현손익·미실현손익을 본다.
- 사용자는 주식·코인 계좌를 합산한 총평가자산·총수익률·평가손익·실현손익을 본다.
- 사용자는 보유 종목별 수량·평균단가·평가금액·미실현손익을 본다.
- 사용자는 자신이 요청한 주문의 매수·매도 구분, 종목, 요청수량, 주문유형, 상태와 요청시각을 본다.
- 사용자는 본인의 체결내역을 최신순으로 넘겨 보며, 매도 건에서 실현손익을 확인한다.

## 요구사항

### ACCT-002 계좌 조회
- [ ] 현금잔고, 보유평가액, 총평가액, 실현손익, 미실현손익을 시장별로 반환한다.
- [ ] 평가값은 저장하지 않고 최신 가격으로 계산한다.

### ACCT-003 전체 포트폴리오 합산 요약
- [ ] `GET /api/portfolio`로 인증 사용자의 `STOCK`·`CRYPTO` 계좌를 합산한다.
- [ ] 총평가자산·총수익률·평가손익·실현손익을 시장별 계좌 요약과 동일한 계산 계약으로 반환한다.
- [ ] 한 시장만 보유하거나 두 시장 모두 비어 있어도 0을 포함한 합산 결과를 반환한다.
- [ ] 합산 결과를 별도 원장으로 저장하지 않고 다른 사용자의 데이터를 포함하지 않는다.

### PORT-001 보유자산
- [ ] 계좌·종목별 보유수량과 평균단가를 제공한다.
- [ ] 현재가·평가금액·미실현손익·수익률은 최신 시세로 계산한다(이슈 #52 반영, PRD `docs/prd.md` PORT-001과 동일 문구).
- [ ] 전량 매도한 종목은 활성 보유목록에서 제외한다.

### PORT-002 거래내역
- [ ] 본인의 시장별 체결내역을 최신순으로 조회한다 (커서 페이지네이션).
- [ ] 체결가격·수량·거래금액·수수료·체결시각을 반환한다.
- [ ] 매도 내역은 FIFO 실현손익을 포함한다.
- [ ] `market`은 필수 파라미터다. 생략 시 여러 시장을 합쳐 조회하는 통합 조회는 지원하지 않는다 (2026-07-28 팀 결정).

### PORT-003 주문 목록
- [ ] `GET /api/orders`로 본인의 주문만 최신순으로 조회한다.
- [ ] 주문 구분, 종목, 요청수량, 주문유형, 주문상태, 주문요청시각을 반환한다.
- [ ] 체결가격·체결금액·수수료·실현손익·체결시각은 중복 반환하지 않고 `GET /api/trades`에서 제공한다.
- [ ] 1차에서 정상 생성된 주문은 시장가 즉시 전량 체결된 `FILLED` 주문이다.
- [ ] MVP에서는 페이지네이션 없이 전체 주문을 반환한다. 페이지네이션은 실제 데이터 증가가 확인되면 후속 고도화로 분리한다. *(이력: 1차 고도화(이슈 #182, `018-order-list-pagination`)에서 `market` 필수 + 커서 페이지네이션(`cursor`·`limit`)으로 확장되었다.)*

## 비즈니스 규칙

- 조회는 원장(MySQL)과 최신 시세(003 계약)만 읽는다 — 평가값을 어디에도 저장하지 않는다.
- 전체 포트폴리오 합산은 시장별 계좌 요약과 동일한 가격·손익 계산 결과를 조합하며 별도 계산식을 만들지 않는다.
- 타인의 계좌·보유·주문·거래내역은 조회할 수 없다 (본인 것만 — 위반 시 403 또는 404).
- 주문 목록은 “무엇을 요청했는가”, 거래내역은 “실제로 얼마에 체결됐는가”를 보여준다. 즉시 체결 구조에서도 두 원장의 의미를 섞지 않는다.
- 시세가 유효하지 않은 종목의 평가값 처리 방식은 plan에서 확정한다 (마지막 유효가 표기 등 — 체결과 달리 조회는 차단하지 않음).
